## Виды соединений

| Соединение | Что вернёт |
|---|---|
| `INNER JOIN` | только пары строк, для которых выполнено условие |
| `LEFT [OUTER] JOIN` | все строки левой таблицы + совпавшие справа; где совпадений нет — справа NULL |
| `RIGHT [OUTER] JOIN` | зеркально: все строки правой |
| `FULL [OUTER] JOIN` | все строки обеих таблиц, недостающая сторона — NULL |
| `CROSS JOIN` | декартово произведение: каждая строка с каждой (N × M строк) |

```sql
SELECT e.last_name, d.department_name
  FROM employees e
  LEFT JOIN departments d ON d.department_id = e.department_id;
```

Сотрудник без отдела попадёт в результат с `department_name = NULL`. При `INNER JOIN` он бы пропал.

## Сколько строк вернёт соединение

Соединение не «добавляет столбцы к строкам», а **перемножает** совпадения. Если у отдела 45 сотрудников, строка отдела повторится 45 раз. Отсюда:

- `INNER JOIN` по связи «один ко многим» вернёт столько строк, сколько строк на стороне «многих» (у которых нашлась пара);
- если ключ соединения не уникален с обеих сторон — строки размножаются, и суммы после соединения раздуваются;
- `LEFT JOIN` вернёт **не меньше** строк, чем в левой таблице.

> **Классическая ошибка:** соединить заказы с позициями и с платежами одновременно, а потом считать `SUM(payment)`. Каждый платёж повторится столько раз, сколько позиций в заказе. Агрегируй каждую ветку отдельно (в подзапросе), а потом соединяй.

## Условие в ON или в WHERE

Для `INNER JOIN` разницы в результате нет. Для внешнего соединения — **принципиальная**:

```sql
-- все отделы, а сотрудники только с зарплатой > 10000
SELECT d.department_name, e.last_name
  FROM departments d
  LEFT JOIN employees e ON e.department_id = d.department_id AND e.salary > 10000;

-- а это уже фактически INNER JOIN: отделы без таких сотрудников пропадут
SELECT d.department_name, e.last_name
  FROM departments d
  LEFT JOIN employees e ON e.department_id = d.department_id
 WHERE e.salary > 10000;
```

Во втором запросе для отделов без сотрудников `e.salary` = NULL, `NULL > 10000` — UNKNOWN, WHERE их отбрасывает. Правило: условие на **правую** таблицу LEFT JOIN — в `ON`; в `WHERE` — только если ты осознанно хочешь отфильтровать результат (например, `WHERE e.employee_id IS NULL` — «отделы без сотрудников», anti-join).

## Self-join и неравенства

**Self-join** — соединение таблицы с самой собой через разные алиасы:

```sql
SELECT e.last_name AS employee, m.last_name AS manager
  FROM employees e
  LEFT JOIN employees m ON m.employee_id = e.manager_id;
```

Условие соединения не обязано быть равенством — например, найти грейд по диапазону: `JOIN job_grades g ON e.salary BETWEEN g.lowest_sal AND g.highest_sal`.

## Старый синтаксис Oracle (+)

До ANSI-синтаксиса внешние соединения в Oracle писали так:

```sql
SELECT e.last_name, d.department_name
  FROM employees e, departments d
 WHERE e.department_id = d.department_id(+);   -- LEFT JOIN departments
```

`(+)` ставится на сторону, **которая может отсутствовать** (где появятся NULL). Ограничения: нельзя сделать FULL OUTER JOIN, нельзя `(+)` с `OR` и `IN`. Встречается в старом коде, на собеседовании любят спросить, с какой стороны ставить плюс.

## Как Oracle соединяет физически

Это уже вопрос производительности, но его задают часто:

| Метод | Как работает | Когда хорош |
|---|---|---|
| **Nested Loops** | для каждой строки внешнего набора ищет пары во внутреннем (обычно по индексу) | мало строк снаружи, есть индекс по ключу внутри |
| **Hash Join** | строит хеш-таблицу по меньшему набору, затем проходит по большему | большие наборы, условие — равенство |
| **Sort Merge Join** | сортирует оба набора по ключу и сливает | условие-неравенство, данные уже отсортированы |

Выбирает оптимизатор по статистике; увидеть выбор можно в плане (`EXPLAIN PLAN`).

## ? Чем INNER JOIN отличается от LEFT JOIN?

INNER JOIN возвращает только строки, у которых нашлась пара в обеих таблицах. LEFT JOIN возвращает все строки левой таблицы; если пары нет, столбцы правой будут NULL. Поэтому LEFT JOIN возвращает не меньше строк, чем в левой таблице, а INNER может вернуть меньше.

## ? Есть ли разница, писать условие в ON или в WHERE?

Для INNER JOIN нет. Для LEFT JOIN — да: условие на правую таблицу в ON ограничивает только то, что присоединяется (левые строки остаются), а то же условие в WHERE отбросит строки, где справа NULL, и LEFT JOIN превратится в INNER. Исключение — специально `WHERE right.id IS NULL` для поиска строк без пары.

## ? Как найти отделы, в которых нет сотрудников?

Три способа: `LEFT JOIN employees e ON … WHERE e.employee_id IS NULL`; `NOT EXISTS (SELECT 1 FROM employees e WHERE e.department_id = d.department_id)`; `MINUS`. Вариант `NOT IN (SELECT department_id FROM employees)` опасен: если в подзапросе есть NULL, вернётся 0 строк.

## ? Что такое CROSS JOIN и когда он нужен?

Декартово произведение: каждая строка левой с каждой строкой правой, N × M строк, условия нет. Нужен редко и осознанно: сгенерировать все комбинации (каждый магазин × каждый день календаря), чтобы потом LEFT JOIN-ом найти пропуски. Случайно получается, когда в старом синтаксисе забыли условие в WHERE.

## ? Что такое self-join? Пример.

Соединение таблицы с самой собой под разными алиасами. Типичный пример — сотрудник и его руководитель: `employees e LEFT JOIN employees m ON m.employee_id = e.manager_id`. LEFT — чтобы не потерять сотрудника без руководителя (директора).

## ? Какие физические методы соединения есть в Oracle?

Nested Loops — для каждой строки внешнего набора поиск во внутреннем (хорош при малом внешнем наборе и индексе). Hash Join — хеш-таблица по меньшему набору и проход по большему (большие объёмы, равенство). Sort Merge — сортировка обоих наборов и слияние (неравенства, уже отсортированные данные). Выбор делает оптимизатор, видно в плане выполнения.

## Тест: Что станет с LEFT JOIN, если условие на правую таблицу (e.salary > 10000) перенести из ON в WHERE?
- Ничего не изменится
- [x] Он по сути станет INNER JOIN
- Он станет FULL JOIN
- Будет ошибка синтаксиса
> У строк без пары `e.salary` = NULL, условие даёт UNKNOWN, и WHERE их выбрасывает — остаются только совпавшие строки.

## Тест: Сколько строк вернёт CROSS JOIN таблиц из 4 и 5 строк?
- 9
- [x] 20
- 5
- 4
> Каждая строка с каждой: 4 × 5 = 20.

## Тест: WHERE e.department_id = d.department_id(+). Какой ANSI-эквивалент?
- employees e RIGHT JOIN departments d
- [x] employees e LEFT JOIN departments d
- employees e FULL JOIN departments d
- employees e INNER JOIN departments d
> `(+)` ставится на сторону, которая может отсутствовать. Отсутствовать может отдел — значит, сохраняются все сотрудники: LEFT JOIN departments.

## Тест: Заказ соединили с 3 позициями и 2 платежами по order_id. Сколько раз повторится каждый платёж в результате?
- 1
- 2
- [x] 3
- 6
> Соединение перемножает совпадения: строк для заказа будет 3 × 2 = 6, и каждый из двух платежей встретится 3 раза. SUM(платежей) окажется втрое больше.

## Тест: Какой метод соединения обычно выбирают для двух больших таблиц с условием-равенством?
- Nested Loops
- [x] Hash Join
- Cartesian Join
- Index Unique Scan
> Hash Join строит хеш-таблицу по меньшему набору и один раз проходит по большему — эффективно на больших объёмах. Nested Loops хорош, когда внешних строк мало и есть индекс.

## Тест: Какой способ найти отделы без сотрудников НЕ надёжен?
- LEFT JOIN … WHERE e.employee_id IS NULL
- NOT EXISTS (…)
- [x] department_id NOT IN (SELECT department_id FROM employees)
- SELECT department_id FROM departments MINUS SELECT department_id FROM employees
> Если у кого-то из сотрудников department_id = NULL, NOT IN вернёт 0 строк. Остальные варианты к NULL устойчивы.
