## Четыре группы команд

| Группа | Расшифровка | Команды | Что делают |
|---|---|---|---|
| **DDL** | Data Definition Language | `CREATE`, `ALTER`, `DROP`, `TRUNCATE`, `RENAME`, `COMMENT` | меняют структуру: таблицы, индексы, процедуры |
| **DML** | Data Manipulation Language | `INSERT`, `UPDATE`, `DELETE`, `MERGE` (+ `SELECT`) | меняют (читают) данные |
| **DCL** | Data Control Language | `GRANT`, `REVOKE` | права доступа |
| **TCL** | Transaction Control Language | `COMMIT`, `ROLLBACK`, `SAVEPOINT`, `SET TRANSACTION` | управляют транзакцией |

`SELECT` иногда выделяют в отдельную группу **DQL** (Data Query Language), но в документации Oracle он относится к DML.

## Главное отличие DDL: неявный COMMIT

В Oracle любая DDL-команда работает так: **COMMIT перед ней, сама команда, COMMIT после неё**. Это значит:

- DDL нельзя откатить через `ROLLBACK`;
- DDL **фиксирует всё, что было сделано в транзакции до неё**, даже если сама DDL упала с ошибкой.

```sql
UPDATE employees SET salary = salary * 2;   -- ещё не зафиксировано
CREATE TABLE tmp_x (id NUMBER);             -- неявный COMMIT!
ROLLBACK;                                   -- зарплаты уже не вернуть
```

DML, наоборот, ничего не фиксирует сам: изменения видны только твоей сессии, пока не будет `COMMIT`.

> **Ловушка:** в PL/SQL DDL напрямую писать нельзя (ошибка компиляции) — только через `EXECUTE IMMEDIATE`. И помни, что такой `EXECUTE IMMEDIATE 'CREATE ...'` внутри процедуры тоже закоммитит всё предыдущее.

## DELETE, TRUNCATE и DROP

Самый частый вопрос этой темы.

| | `DELETE` | `TRUNCATE` | `DROP` |
|---|---|---|---|
| Группа | DML | DDL | DDL |
| Что удаляет | выбранные строки (`WHERE`) или все | все строки | всю таблицу: данные, структуру, индексы, права |
| Можно `WHERE` | да | нет | нет |
| Откат `ROLLBACK` | да | нет (неявный COMMIT) | нет (но есть корзина: `FLASHBACK TABLE … TO BEFORE DROP`) |
| Скорость на большой таблице | медленно: пишет undo и redo на каждую строку | быстро: освобождает сегменты целиком | быстро |
| Триггеры `ON DELETE` | срабатывают | не срабатывают | не срабатывают |
| Место на диске | не освобождает, HWM остаётся | сбрасывает HWM, место освобождается | освобождает |
| Если есть ссылающиеся FK | проверяет каждую строку | ошибка ORA-02266, если на таблицу ссылается включённый FK | ошибка, если не `CASCADE CONSTRAINTS` |

**HWM (High Water Mark)** — отметка «до сюда в сегменте когда-то были данные». Полное сканирование таблицы читает всё до HWM. После `DELETE` всех строк таблица пустая, но сканирование всё равно читает все старые блоки; после `TRUNCATE` — нет.

## TRUNCATE подробнее

```sql
TRUNCATE TABLE stage_orders;                  -- освободить место
TRUNCATE TABLE stage_orders REUSE STORAGE;    -- оставить выделенные экстенты себе
```

Типичное применение — очистка промежуточных (staging) таблиц перед загрузкой. Нюансы:

- нужна привилегия на таблицу уровня DDL (владелец или `DROP ANY TABLE`);
- нельзя, если на таблицу ссылается **включённый** внешний ключ (даже если дочерняя таблица пустая) — в 12c+ есть `TRUNCATE … CASCADE` для FK с `ON DELETE CASCADE`;
- последовательности и `IDENTITY` не сбрасываются (для identity нужен `ALTER TABLE … MODIFY … RESTART`).

## MERGE — вставить или обновить

`MERGE` — DML-команда «upsert»: для каждой строки источника либо обновить совпавшую строку цели, либо вставить новую.

```sql
MERGE INTO employees_copy t
USING (SELECT employee_id, salary FROM employees) s
   ON (t.employee_id = s.employee_id)
 WHEN MATCHED THEN UPDATE SET t.salary = s.salary
 WHEN NOT MATCHED THEN INSERT (employee_id, salary) VALUES (s.employee_id, s.salary);
```

Нельзя обновлять столбцы из условия `ON`. Если одной строке цели соответствуют две строки источника — ошибка `ORA-30926: unable to get a stable set of rows`.

## ? Чем DELETE отличается от TRUNCATE?

`DELETE` — DML: удаляет строки по условию, пишет undo на каждую строку, его можно откатить, срабатывают триггеры, место не освобождается (HWM остаётся). `TRUNCATE` — DDL: удаляет все строки сразу, неявно коммитит, откатить нельзя, триггеры на DELETE не срабатывают, работает почти мгновенно и сбрасывает HWM. TRUNCATE не сработает, если на таблицу ссылается включённый внешний ключ.

## ? А чем TRUNCATE отличается от DROP?

`TRUNCATE` удаляет только данные — таблица, её столбцы, индексы, ограничения, права и триггеры остаются. `DROP` удаляет саму таблицу со всем этим. После `DROP` таблица по умолчанию попадает в корзину (recycle bin), и её можно вернуть `FLASHBACK TABLE … TO BEFORE DROP`; `DROP … PURGE` удаляет безвозвратно.

## ? Что такое DDL, DML, DCL, TCL? Приведи примеры.

DDL — определение структуры: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`. DML — работа с данными: `INSERT`, `UPDATE`, `DELETE`, `MERGE`, `SELECT`. DCL — права: `GRANT`, `REVOKE`. TCL — транзакции: `COMMIT`, `ROLLBACK`, `SAVEPOINT`. Главное практическое отличие: DDL в Oracle делает неявный COMMIT до и после себя.

## ? Можно ли откатить CREATE TABLE или ALTER TABLE?

Нет. DDL в Oracle выполняется с неявным COMMIT до и после себя, поэтому откатить его нельзя, а заодно фиксируются все незакоммиченные изменения, сделанные перед ним. Ошибочно удалённую таблицу можно вернуть из корзины `FLASHBACK TABLE`, а данные — с помощью Flashback Query, если хватает undo.

## ? Что такое MERGE и когда его используют?

Команда «вставить или обновить» за один проход: строки источника сопоставляются с целью по условию `ON`, совпавшие обновляются (`WHEN MATCHED`), остальные вставляются (`WHEN NOT MATCHED`). Типичный случай — синхронизация справочника или загрузка из staging-таблицы. Столбцы из `ON` обновлять нельзя; дубль в источнике даёт ORA-30926.

## Тест: Какая из команд относится к DDL?
- DELETE
- MERGE
- [x] TRUNCATE
- COMMIT
> `TRUNCATE` — DDL: меняет сегменты таблицы и делает неявный COMMIT. `DELETE` и `MERGE` — DML, `COMMIT` — TCL.

## Тест: Выполнили UPDATE, затем CREATE TABLE tmp(...), затем ROLLBACK. Что с изменениями UPDATE?
- Откатятся вместе с CREATE TABLE
- Откатятся, а таблица tmp останется
- [x] Останутся: CREATE TABLE их закоммитил
- Будет ошибка: нельзя DDL в незакрытой транзакции
> DDL в Oracle — это COMMIT, команда, COMMIT. Незакоммиченный UPDATE зафиксировался в момент CREATE TABLE, откатывать уже нечего.

## Тест: Нужно удалить из таблицы 50 млн строк — все, без условия, с возможностью быстро освободить место. Что выбрать?
- DELETE FROM t
- [x] TRUNCATE TABLE t
- DROP TABLE t
- DELETE FROM t WHERE 1=1
> TRUNCATE не пишет undo на каждую строку, работает почти мгновенно и сбрасывает HWM. DROP удалил бы и саму таблицу.

## Тест: Срабатывает ли триггер AFTER DELETE ON t при TRUNCATE TABLE t?
- Да, для каждой строки
- Да, один раз как statement-триггер
- [x] Нет
- Только если триггер объявлен FOR EACH ROW
> TRUNCATE — не DML, строки он не удаляет «по одной», поэтому DML-триггеры не срабатывают. Это один из аргументов, почему TRUNCATE нельзя использовать вместо DELETE, если на удаление завязана логика.

## Тест: Что произойдёт при TRUNCATE таблицы departments, если на неё ссылается включённый FK из employees?
- Удалятся и сотрудники
- У сотрудников department_id станет NULL
- [x] Ошибка ORA-02266
- TRUNCATE выполнится, FK станет невалидным
> Если на таблицу ссылается включённый внешний ключ, TRUNCATE запрещён (даже если дочерняя таблица пустая). Нужно сначала отключить FK или использовать DELETE.

## Тест: После DELETE всех строк из большой таблицы полный SELECT COUNT(*) всё ещё медленный. Почему?
- Строки ещё не удалены до COMMIT
- [x] High Water Mark остался на месте, и сканирование читает все старые блоки
- Индекс по таблице стал невалидным
- Oracle кэширует старый результат
> DELETE не сдвигает HWM: блоки пустые, но полное сканирование читает всё до отметки. TRUNCATE (или `ALTER TABLE … SHRINK SPACE` / `MOVE`) возвращает HWM назад.

## Тест: Что вернёт таблицу после DROP TABLE emp (без PURGE)?
- ROLLBACK
- [x] FLASHBACK TABLE emp TO BEFORE DROP
- UNDROP TABLE emp
- Ничего, таблица удалена безвозвратно
> Без `PURGE` таблица попадает в корзину (recycle bin), и `FLASHBACK TABLE … TO BEFORE DROP` её возвращает вместе с данными и индексами. `ROLLBACK` не поможет — DROP уже закоммичен.
