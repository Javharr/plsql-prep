## Что такое транзакция

**Транзакция** — набор операций, который выполняется как одно целое: либо все изменения фиксируются, либо ни одного. Классический пример — перевод денег: списать со счёта A и зачислить на счёт B. Если после списания сервер упал, деньги не должны исчезнуть.

```sql
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
```

В Oracle транзакция **начинается неявно** — с первой DML-команды — и заканчивается:

- `COMMIT` — изменения фиксируются и становятся видны другим сессиям;
- `ROLLBACK` — изменения отменяются;
- любой DDL — неявный COMMIT;
- нормальный выход из клиента (обычно COMMIT, зависит от инструмента) или обрыв сессии (ROLLBACK).

Явного `BEGIN TRANSACTION` в Oracle нет. Режим autocommit — это настройка клиента (SQL Developer, DataGrip, драйвер), а не базы.

## ACID

| Буква | Свойство | Смысл | Как обеспечивает Oracle |
|---|---|---|---|
| **A** | Atomicity — атомарность | всё или ничего | undo: при ROLLBACK или сбое изменения откатываются |
| **C** | Consistency — согласованность | транзакция переводит базу из одного корректного состояния в другое: ограничения не нарушены | ограничения целостности, триггеры, логика приложения |
| **I** | Isolation — изоляция | параллельные транзакции не мешают друг другу (насколько — зависит от уровня изоляции) | блокировки строк + согласованное чтение из undo |
| **D** | Durability — долговечность | после COMMIT данные не потеряются даже при сбое | redo log: COMMIT ждёт записи redo на диск |

## SAVEPOINT — частичный откат

```sql
INSERT INTO orders (...) VALUES (...);
SAVEPOINT after_order;
INSERT INTO order_items (...) VALUES (...);   -- что-то пошло не так
ROLLBACK TO SAVEPOINT after_order;            -- позиции откатились, заказ остался
COMMIT;
```

`ROLLBACK TO SAVEPOINT` не завершает транзакцию: она продолжается, и в конце всё равно нужен COMMIT или ROLLBACK. Точки сохранения после указанной отменяются.

## Атомарность одной команды

Каждая отдельная команда в Oracle атомарна сама по себе (**statement-level atomicity**). Если `UPDATE` 1000 строк упал на 600-й (например, нарушение CHECK), откатятся все 600 изменений **этой команды** — но предыдущие команды транзакции останутся нетронутыми, и транзакция продолжится.

В PL/SQL то же для блока: если необработанное исключение вылетело из анонимного блока к клиенту, Oracle откатывает изменения **этого вызова** (неявный savepoint перед ним), а изменения, сделанные раньше в транзакции, остаются.

## Undo и redo — механика

**Undo** (сегменты отката) хранит старые версии изменённых данных. Нужен для трёх вещей:

1. откатить транзакцию (ROLLBACK);
2. **согласованное чтение** — другие сессии видят данные такими, какими они были до твоих незакоммиченных изменений (и на момент начала их запроса);
3. Flashback Query: `SELECT … AS OF TIMESTAMP SYSTIMESTAMP - INTERVAL '10' MINUTE`.

**Redo** (журнал повторного выполнения) хранит описание всех изменений. Нужен для **восстановления**: если сервер упал, Oracle при старте «накатывает» redo, чтобы не потерять закоммиченное, и с помощью undo откатывает незакоммиченное. Поэтому COMMIT быстрый: он не пишет сами блоки данных на диск, а только дожидается записи redo (процесс LGWR).

> **Ошибка ORA-01555 snapshot too old** — длинный запрос не смог найти в undo старую версию блока: её уже перезаписали. Лечится увеличением undo-пространства и отказом от `COMMIT` внутри цикла по открытому курсору.

## Транзакции и PL/SQL

- Процедура **не** коммитит сама по себе — транзакцией управляет тот, кто её вызвал. Хорошая практика: COMMIT в одном месте, в коде верхнего уровня, а не в каждой процедуре.
- `COMMIT` внутри цикла на каждой строке — антипаттерн: медленно (ожидание redo каждый раз), ломает атомарность (половина данных зафиксирована при сбое) и провоцирует ORA-01555.
- Отдельная независимая транзакция внутри процедуры — `PRAGMA AUTONOMOUS_TRANSACTION` (логирование ошибок), см. тему про PL/SQL-транзакции.

## ? Что такое транзакция? Расшифруй ACID.

Транзакция — набор операций, выполняемый как единое целое: всё или ничего. ACID: Atomicity — все изменения применяются или ни одно; Consistency — база переходит из одного корректного состояния в другое, ограничения соблюдены; Isolation — параллельные транзакции не видят промежуточных результатов друг друга (в меру уровня изоляции); Durability — после COMMIT данные сохранятся даже при сбое.

## ? Как Oracle обеспечивает атомарность и долговечность?

Атомарность — через undo: там хранятся старые версии данных, по ним Oracle откатывает изменения при ROLLBACK или сбое. Долговечность — через redo log: COMMIT возвращает управление только после того, как запись об изменениях попала на диск; после сбоя Oracle накатывает redo и откатывает незакоммиченное по undo.

## ? Когда в Oracle начинается и заканчивается транзакция?

Начинается неявно с первой DML-команды (или SET TRANSACTION). Заканчивается COMMIT, ROLLBACK, любой DDL-командой (неявный COMMIT), отключением сессии (при аварийном — ROLLBACK). Команды BEGIN TRANSACTION, как в других СУБД, нет.

## ? Что такое SAVEPOINT?

Именованная точка внутри транзакции, до которой можно откатиться: `ROLLBACK TO SAVEPOINT имя`. Изменения после точки отменяются, до неё — остаются, транзакция продолжается. Применяется, когда часть работы можно отменить, не теряя всё.

## ? Почему COMMIT в цикле — плохая идея?

Медленно: каждый COMMIT ждёт записи redo на диск. Ломает атомарность: при сбое на середине половина данных уже зафиксирована, перезапуск сложнее. При чтении из курсора, по таблице которого идут изменения, растёт риск ORA-01555 snapshot too old. Правильно — одна транзакция на логическую единицу работы, а большие объёмы — BULK/FORALL или порциями с продуманным перезапуском.

## ? Что такое undo и redo и чем они отличаются?

Undo хранит старые версии данных — нужен для ROLLBACK, согласованного чтения и Flashback. Redo хранит описание изменений — нужен для восстановления после сбоя (накатить закоммиченное). Коротко: undo — чтобы отменить, redo — чтобы повторить.
