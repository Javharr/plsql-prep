## Процедура и функция

Обе — именованные блоки, которые хранятся в базе в скомпилированном виде и вызываются по имени.

```sql
CREATE OR REPLACE PROCEDURE raise_salary (p_emp_id IN NUMBER, p_pct IN NUMBER DEFAULT 10) IS
BEGIN
  UPDATE employees SET salary = salary * (1 + p_pct / 100) WHERE employee_id = p_emp_id;
  IF SQL%ROWCOUNT = 0 THEN
    RAISE_APPLICATION_ERROR(-20001, 'Нет сотрудника ' || p_emp_id);
  END IF;
END raise_salary;
/

CREATE OR REPLACE FUNCTION annual_salary (p_emp_id NUMBER) RETURN NUMBER IS
  v NUMBER;
BEGIN
  SELECT salary * 12 INTO v FROM employees WHERE employee_id = p_emp_id;
  RETURN v;
END;
/
```

| | Процедура | Функция |
|---|---|---|
| Назначение | выполнить действие | вычислить и **вернуть значение** |
| RETURN | не обязателен, без значения | `RETURN значение` обязателен; если функция дошла до END без RETURN — ошибка ORA-06503 |
| Вызов | отдельной командой | в выражении: `v := f(x)` |
| В SQL (`SELECT f(x) FROM …`) | нельзя | можно, если соблюдены ограничения |

Обе могут иметь OUT-параметры, но функция с OUT-параметрами — плохой стиль, и её уже нельзя вызвать из SQL.

## Режимы параметров

| Режим | Внутри подпрограммы | Что передаётся |
|---|---|---|
| `IN` (по умолчанию) | только чтение | значение (на деле — ссылка, это быстро) |
| `OUT` | запись (на входе — NULL) | результат возвращается вызывающему |
| `IN OUT` | чтение и запись | значение туда и обратно |

Фактический параметр для OUT и IN OUT должен быть **переменной**, а не литералом или выражением.

**NOCOPY** — подсказка передавать OUT/IN OUT по ссылке, а не копировать. Ускоряет передачу больших коллекций. Цена: если внутри возникло исключение, при обычной передаче значение переменной у вызывающего останется прежним, а с NOCOPY — может остаться частично изменённым.

## Позиционная и именованная передача

```sql
raise_salary(100, 5);                         -- позиционная
raise_salary(p_pct => 5, p_emp_id => 100);    -- именованная, порядок любой
raise_salary(100, p_pct => 5);                -- смешанная: сначала позиционные
raise_salary(100);                            -- p_pct возьмёт DEFAULT 10
```

Именованная нотация читаемее и не ломается при добавлении новых параметров со значениями по умолчанию в конец списка.

## Функции в SQL и их ограничения

Функцию можно вызвать в `SELECT`, `WHERE`, `ORDER BY`, если:

- все параметры — режима IN и SQL-типов (не BOOLEAN до 23ai, не записи PL/SQL);
- функция не выполняет DML (иначе при вызове из SELECT — `ORA-14551: cannot perform a DML operation inside a query`), не делает COMMIT/ROLLBACK;
- при вызове из UPDATE/DELETE она не читает изменяемую таблицу (ORA-04091).

Обход для DML — `PRAGMA AUTONOMOUS_TRANSACTION`, но это почти всегда признак неправильного дизайна.

**Производительность:** функция в SQL вызывается на каждую строку и каждый раз переключает контекст. Что помогает:

- `DETERMINISTIC` — пометка «при одинаковых аргументах один результат»; нужна для функциональных индексов, позволяет Oracle не вызывать функцию повторно в пределах запроса;
- `RESULT_CACHE` — результаты кешируются в SGA между вызовами и сессиями, сбрасываются при изменении зависимых таблиц;
- `PRAGMA UDF` (12c+) — компиляция с расчётом на вызов из SQL;
- скалярный подзапрос `(SELECT f(x) FROM dual)` — включает кэширование скалярных подзапросов;
- лучше всего — переписать логику прямо на SQL.

## Права: AUTHID DEFINER и CURRENT_USER

- `AUTHID DEFINER` (по умолчанию) — подпрограмма выполняется с правами **владельца**, имена таблиц разрешаются в его схеме. Пользователю достаточно `EXECUTE` на процедуру — прямой доступ к таблицам ему не нужен. Это основа инкапсуляции.
- `AUTHID CURRENT_USER` — с правами **вызывающего**, имена — в его схеме. Нужно для общих утилит, которые работают с объектами того, кто вызвал.

## Локальные подпрограммы, перегрузка, зависимость

- Внутри процедуры можно объявить вложенную процедуру или функцию в разделе объявлений — она видна только там.
- Хранимые объекты отслеживают **зависимости**: если изменить таблицу, процедура, которая её использует, становится `INVALID` и перекомпилируется при следующем вызове (или вызывает ошибку, если код больше не корректен). Смотреть — `user_dependencies`, `user_objects.status`, ошибки компиляции — `user_errors` / `SHOW ERRORS`.
- Перегрузка (одно имя, разные параметры) возможна в пакетах и для локальных подпрограмм, но не для отдельных хранимых процедур.

## ? Чем процедура отличается от функции?

Функция обязана вернуть значение через RETURN и вызывается в выражении, в том числе в SQL-запросе (при соблюдении ограничений). Процедура выполняет действие, вызывается отдельной командой и возвращает данные только через OUT-параметры. Если функция дошла до конца без RETURN — ORA-06503.

## ? Какие режимы параметров бывают?

IN — входной, только для чтения, режим по умолчанию. OUT — выходной: внутри начинается с NULL, значение возвращается вызывающему. IN OUT — передаётся внутрь и возвращается изменённым. Для OUT и IN OUT фактическим параметром должна быть переменная.

## ? Что такое NOCOPY?

Подсказка компилятору передавать OUT и IN OUT параметры по ссылке, без копирования туда и обратно. Ускоряет работу с большими коллекциями. Риск: при исключении внутри подпрограммы переменная вызывающего может остаться частично изменённой, тогда как без NOCOPY она сохранила бы исходное значение.

## ? Можно ли вызвать функцию из SELECT? Какие ограничения?

Можно, если параметры только IN и SQL-типов, функция не делает DML и не управляет транзакцией (иначе ORA-14551), а при вызове из DML не читает изменяемую таблицу. Из-за переключения контекста на каждой строке стоит подумать о DETERMINISTIC, RESULT_CACHE, PRAGMA UDF или переписать логику на SQL.

## ? Что такое DETERMINISTIC и RESULT_CACHE?

DETERMINISTIC — обещание, что функция при одинаковых аргументах возвращает одинаковый результат; Oracle может не вызывать её повторно в пределах запроса, и только такую функцию можно использовать в функциональном индексе. RESULT_CACHE — результаты вызовов кешируются в SGA для всех сессий и автоматически сбрасываются при изменении таблиц, от которых функция зависит.

## ? Чем AUTHID DEFINER отличается от CURRENT_USER?

DEFINER (по умолчанию) — код выполняется с правами владельца и видит объекты его схемы; вызывающему достаточно EXECUTE, прямых прав на таблицы не нужно. CURRENT_USER — с правами и в схеме вызывающего; нужен для общих утилит. Помни: в DEFINER-коде не действуют права, выданные через роли.

## ? Почему процедура стала INVALID и что с этим делать?

Изменился объект, от которого она зависит: таблица (добавили или удалили столбец), представление, спецификация пакета. Oracle помечает зависимые объекты как INVALID и пытается перекомпилировать при следующем вызове. Если код всё ещё корректен — всё заработает; если нет — ошибка. Найти — user_objects WHERE status = 'INVALID', причины — user_errors, перекомпилировать — ALTER PROCEDURE … COMPILE или DBMS_UTILITY.COMPILE_SCHEMA.

## Тест: Что произойдёт, если функция дошла до END без выполнения RETURN?
- Вернёт NULL
- Вернёт 0

- Ошибка компиляции
> Компилятор не всегда может это отследить, поэтому ошибка возникает при выполнении. Каждая ветка функции должна заканчиваться RETURN.

## Тест: Какое значение у OUT-параметра в начале выполнения процедуры?
- Значение переменной вызывающего
- [x] NULL
- 0
- Значение по умолчанию из DEFAULT
> OUT-параметр предназначен только для возврата результата, на входе он NULL. Передать значение внутрь и вернуть — IN OUT.

## Тест: Функция делает INSERT в таблицу логов. Что будет при вызове SELECT f(id) FROM t?
- Всё выполнится, строки вставятся
- [x] ORA-14551: cannot perform a DML operation inside a query
- Вставка выполнится, но откатится в конце запроса
- Ошибка компиляции функции
> Функции, вызываемые из запроса, не могут менять данные. Логирование в таком случае делают автономной транзакцией.

## Тест: Какой вызов правильный для процедуры p(a NUMBER, b NUMBER DEFAULT 1)?
- p(b => 2, 5)
- [x] p(5, b => 2)
- p(a = 5)
- p(=> 5)
> При смешанной нотации позиционные параметры идут первыми. Именованная передача — через `=>`.

## Тест: Какая функция может участвовать в функциональном индексе?
- Любая функция без параметров
- Функция с RESULT_CACHE
- [x] Функция с DETERMINISTIC
- Функция с OUT-параметром
> Индекс хранит вычисленное значение, поэтому функция обязана давать одинаковый результат при одинаковых аргументах — DETERMINISTIC.
