## Строки: VARCHAR2, CHAR, CLOB

| Тип | Что хранит |
|---|---|
| `VARCHAR2(n)` | строка переменной длины до n (до 4000 байт в SQL, до 32767 при `MAX_STRING_SIZE=EXTENDED`) |
| `CHAR(n)` | строка **фиксированной** длины: короче — дополняется пробелами до n |
| `NVARCHAR2`, `NCHAR` | то же в национальной кодировке |
| `CLOB` | большой текст (гигабайты) |

`VARCHAR` сейчас синоним `VARCHAR2`, но Oracle оставляет за собой право изменить его смысл — в коде пишут `VARCHAR2`.

**Байты или символы:** `VARCHAR2(10)` по умолчанию — 10 **байт** (параметр `NLS_LENGTH_SEMANTICS`). В UTF-8 кириллица занимает 2 байта, поэтому «Привет мир» туда не влезет. Явно: `VARCHAR2(10 CHAR)`.

Ловушка CHAR: `CHAR(5)` со значением `'ab'` хранится как `'ab   '`. Сравнение двух CHAR дополняет пробелами и находит совпадение, а сравнение CHAR с VARCHAR2-переменной — нет.

## Числа: NUMBER

`NUMBER(p, s)` — точность p (всего значащих цифр, до 38) и масштаб s (цифр после запятой).

| Объявление | Значение 1234.567 |
|---|---|
| `NUMBER` | 1234.567 |
| `NUMBER(6,2)` | 1234.57 (округлено) |
| `NUMBER(6)` | 1235 |
| `NUMBER(3)` | ошибка ORA-01438: значение больше точности |

`NUMBER` хранит десятичные числа точно — подходит для денег. `BINARY_DOUBLE`/`BINARY_FLOAT` — двоичная плавающая точка: быстрее в вычислениях, но 0.1 хранится приблизительно. `INTEGER` — это `NUMBER(38)`. В PL/SQL есть `PLS_INTEGER` — быстрая целочисленная арифметика.

## DATE и TIMESTAMP

- `DATE` хранит **дату и время до секунд** (не только дату!). Без часового пояса.
- `TIMESTAMP` — до долей секунды (по умолчанию 6 знаков).
- `TIMESTAMP WITH TIME ZONE` — с поясом; `WITH LOCAL TIME ZONE` — приводится к поясу сессии.

```sql
SELECT SYSDATE, SYSTIMESTAMP FROM dual;
SELECT DATE '2024-03-01', TIMESTAMP '2024-03-01 10:30:00' FROM dual;   -- ANSI-литералы
```

Арифметика с DATE — в днях: `SYSDATE + 1` — завтра в это же время, `SYSDATE + 1/24` — через час, разность двух DATE — число дней (дробное). Разность TIMESTAMP — `INTERVAL`.

Полезные функции: `TRUNC(d)` — отрезать время (полночь), `TRUNC(d, 'MM')` — первое число месяца, `ADD_MONTHS(d, n)`, `MONTHS_BETWEEN(a, b)`, `LAST_DAY(d)`, `NEXT_DAY(d, 'MONDAY')`, `EXTRACT(YEAR FROM d)`.

> **Ловушка:** `WHERE hire_date = DATE '2024-03-01'` не найдёт строку со временем 14:30 того же дня. Нужно `WHERE hire_date >= DATE '2024-03-01' AND hire_date < DATE '2024-03-02'` (индекс работает) или `TRUNC(hire_date) = …` (индекс по hire_date не работает).

## Преобразования: явные и неявные

Явные: `TO_CHAR(дата|число, формат)`, `TO_DATE(строка, формат)`, `TO_NUMBER(строка, формат)`, `CAST(x AS тип)`.

```sql
SELECT TO_CHAR(SYSDATE, 'DD.MM.YYYY HH24:MI') FROM dual;
SELECT TO_DATE('01.03.2024', 'DD.MM.YYYY') FROM dual;
SELECT TO_CHAR(1234567.8, 'FM9G999G990D00') FROM dual;
```

Частые маски: `YYYY` — год, `MM` — месяц, `MI` — **минуты** (не путать с `MM`), `HH24` — часы 0–23, `DY`/`DAY` — день недели, `FM` — убрать лишние пробелы и ведущие нули.

**Неявное преобразование** Oracle делает сам: `'10' + 5` = 15, `WHERE hire_date = '01-MAR-24'` — строка превращается в дату **по формату сессии** `NLS_DATE_FORMAT`. Это ломается при другой настройке клиента и выключает индексы (если преобразуется столбец). Правило: всегда явно `TO_DATE` с маской или литерал `DATE '…'`.

## CASE и DECODE

```sql
SELECT last_name,
       CASE WHEN salary >= 10000 THEN 'высокая'
            WHEN salary >= 5000  THEN 'средняя'
            ELSE 'низкая' END AS level,
       DECODE(department_id, 10, 'Admin', 20, 'Marketing', 'Другой') AS dept
  FROM employees;
```

| | CASE | DECODE |
|---|---|---|
| Стандарт | ANSI SQL | только Oracle |
| Условия | любые (`>`, `BETWEEN`, `IN`, …) | только равенство |
| NULL | `CASE x WHEN NULL` не срабатывает | `DECODE(x, NULL, …)` срабатывает |
| В PL/SQL | можно как выражение и как оператор | только внутри SQL |

Обе вычисляются до первого совпадения; без ELSE (без значения по умолчанию) — NULL.

## ? Чем VARCHAR2 отличается от CHAR?

VARCHAR2 хранит строку переменной длины — столько, сколько записали. CHAR — фиксированной: короткое значение дополняется пробелами до объявленной длины. Из-за пробелов сравнения CHAR с VARCHAR2 дают неожиданные результаты, поэтому почти всегда используют VARCHAR2. CHAR(1) иногда берут для флагов 'Y'/'N'.

## ? Чем DATE отличается от TIMESTAMP?

DATE хранит дату и время с точностью до секунды, без часового пояса. TIMESTAMP — с долями секунды, есть варианты с часовым поясом. Разность двух DATE — число дней, разность TIMESTAMP — INTERVAL. Частая ошибка — думать, что DATE хранит только дату.

## ? Как правильно выбрать все строки за конкретный день?

Диапазоном: `WHERE dt >= DATE '2024-03-01' AND dt < DATE '2024-03-02'`. Так учитывается время внутри дня и работает индекс по dt. `WHERE dt = DATE '2024-03-01'` найдёт только полночь, `TRUNC(dt) = …` правильно, но выключает обычный индекс по dt.

## ? Чем CASE отличается от DECODE?

CASE — стандарт SQL, поддерживает любые условия, работает и в SQL, и в PL/SQL. DECODE — функция Oracle, умеет только проверку на равенство, используется только внутри SQL. Отличие в NULL: DECODE считает NULL равным NULL, а простой CASE x WHEN NULL — нет.

## ? Что такое неявное преобразование типов и чем оно опасно?

Oracle сам приводит типы при несовпадении: строку к числу, строку к дате по NLS_DATE_FORMAT сессии. Опасно тем, что результат зависит от настроек клиента (у другого пользователя формат другой — ошибка ORA-01861), и тем, что преобразование столбца выключает индекс. Пиши явно: TO_DATE с маской, литералы DATE '…', сравнивай строки со строками.

## ? Какой тип выбрать для денежных сумм?

NUMBER с явным масштабом, например NUMBER(12,2): он хранит десятичные числа точно. BINARY_DOUBLE/FLOAT для денег не подходят — двоичная плавающая точка даёт ошибки округления (0.1 + 0.2 ≠ 0.3).

## Тест: Что хранит тип DATE в Oracle?
- Только дату
- [x] Дату и время до секунды
- Дату и время с миллисекундами
- Дату, время и часовой пояс
> DATE — это год, месяц, день, часы, минуты, секунды. Доли секунды и часовой пояс — у TIMESTAMP.

## Тест: Чему равно SYSDATE + 1/24?
- Завтра
- [x] Через час
- Через минуту
- Ошибка: нельзя прибавить дробь
> Арифметика DATE — в днях: 1/24 дня — один час. 1/1440 — минута.

## Тест: Какая маска даёт минуты в TO_CHAR?
- MM
- [x] MI
- MN
- HH:MM
> `MM` — месяц, `MI` — минуты. Частая ошибка — `HH24:MM`, которая выводит месяц вместо минут.

## Тест: Что произойдёт при вставке 1234.567 в столбец NUMBER(5,2)?
- Сохранится 1234.57
- Сохранится 1234.56
- [x] Ошибка ORA-01438
- Сохранится 234.57
> NUMBER(5,2) — всего 5 цифр, из них 2 после запятой, то есть до 999.99. Для 1234.57 нужно 6 цифр.

## Тест: Какое выражение срабатывает для x = NULL?
- CASE x WHEN NULL THEN 'пусто' END
- [x] DECODE(x, NULL, 'пусто')
- CASE WHEN x = NULL THEN 'пусто' END
- NULLIF(x, NULL)
> DECODE считает NULL равным NULL. В CASE нужно `WHEN x IS NULL`.

## Тест: Строка 'Привет мир' (10 символов, UTF-8) и столбец VARCHAR2(10) с байтовой семантикой. Что будет?
- Сохранится полностью
- Сохранятся первые 10 байт
- [x] Ошибка ORA-12899: значение слишком большое
- Сохранится в CLOB
> Кириллица в UTF-8 — 2 байта на символ, строке нужно около 19 байт. Объявляй `VARCHAR2(10 CHAR)`.

## Тест: Почему WHERE hire_date = '01.03.2024' может работать у тебя и падать у коллеги?
- У коллеги другая версия Oracle
- [x] Строка неявно превращается в дату по NLS_DATE_FORMAT сессии, а он у коллеги другой
- Индекс у коллеги невалиден
- Нужен COMMIT
> Неявное преобразование зависит от настроек сессии. Надёжно — `DATE '2024-03-01'` или `TO_DATE('01.03.2024', 'DD.MM.YYYY')`.
