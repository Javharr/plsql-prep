## Логический порядок выполнения

Пишем запрос в одном порядке, а логически он вычисляется в другом:

| Шаг | Часть | Что происходит |
|---|---|---|
| 1 | `FROM` / `JOIN` | собираются исходные строки, соединяются таблицы |
| 2 | `WHERE` | отбрасываются строки, не прошедшие условие |
| 3 | `GROUP BY` | оставшиеся строки собираются в группы |
| 4 | `HAVING` | отбрасываются группы |
| 5 | `SELECT` | вычисляются выражения и **алиасы** столбцов, `DISTINCT` |
| 6 | `ORDER BY` | сортировка результата |
| 7 | `OFFSET` / `FETCH FIRST` | отсечение строк |

Это *логический* порядок — оптимизатор может выполнять физически иначе (например, применить условие раньше), но результат обязан совпадать с этим порядком.

## Что из этого следует

**Алиас из SELECT нельзя использовать в WHERE, GROUP BY и HAVING** — на шагах 2–4 его ещё не существует:

```sql
SELECT salary * 12 AS annual FROM employees WHERE annual > 100000;   -- ORA-00904
SELECT salary * 12 AS annual FROM employees WHERE salary * 12 > 100000; -- так
```

А в `ORDER BY` алиас использовать **можно** — сортировка идёт после SELECT.

**Агрегатную функцию нельзя писать в WHERE** — группы ещё не построены. Условие по агрегату — только в `HAVING`:

```sql
SELECT department_id, AVG(salary)
  FROM employees
 GROUP BY department_id
HAVING AVG(salary) > 8000;
```

**ROWNUM назначается до ORDER BY** (на шаге WHERE), поэтому `WHERE ROWNUM <= 5 ORDER BY salary DESC` берёт пять случайных строк и сортирует только их. Правильно — `FETCH FIRST 5 ROWS ONLY` или подзапрос с сортировкой.

## WHERE против HAVING

- `WHERE` фильтрует **строки** до группировки; агрегаты в нём запрещены.
- `HAVING` фильтрует **группы** после группировки; в нём можно агрегаты.

Условие, не использующее агрегаты (`department_id = 50`), технически можно написать и в HAVING, но лучше в WHERE: строки отбросятся раньше, и группировать придётся меньше.

## GROUP BY: правило одной строки на группу

После `GROUP BY` каждая группа превращается в **одну** строку результата. Поэтому в SELECT можно писать только:

- столбцы (выражения), перечисленные в `GROUP BY`;
- агрегатные функции;
- константы.

```sql
SELECT department_id, job_id, COUNT(*)
  FROM employees
 GROUP BY department_id;     -- ORA-00979: not a GROUP BY expression
```

`job_id` не в GROUP BY: в отделе много должностей, какую из них выводить в одной строке — непонятно.

Агрегат без GROUP BY превращает весь набор строк в одну группу: `SELECT COUNT(*) FROM employees` — одна строка. И даже если строк нет, `COUNT(*)` вернёт одну строку с 0, а `MAX` — одну строку с NULL.

## Агрегатные функции и NULL

`SUM`, `AVG`, `MIN`, `MAX`, `COUNT(столбец)` **игнорируют NULL**. Отсюда классические ловушки:

| Выражение | Что считает |
|---|---|
| `COUNT(*)` | все строки |
| `COUNT(commission_pct)` | строки, где commission_pct не NULL |
| `COUNT(DISTINCT department_id)` | разные непустые значения |
| `AVG(commission_pct)` | среднее **только по заполненным** |
| `AVG(NVL(commission_pct, 0))` | среднее по всем, NULL как 0 |
| `SUM(x)` по пустому набору | NULL, а не 0 |

Итоги: `ROLLUP(a, b)` добавляет промежуточные и общие итоги, `CUBE` — итоги по всем комбинациям, `GROUPING SETS` — нужные наборы явно. Функция `GROUPING(col)` отличает строку итога (1) от обычного NULL в данных (0).

## ? В каком порядке выполняется SELECT-запрос?

Логически: `FROM`/`JOIN` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` (выражения, алиасы, DISTINCT) → `ORDER BY` → `FETCH FIRST`. Следствия: алиас столбца нельзя использовать в WHERE и GROUP BY, но можно в ORDER BY; агрегаты нельзя в WHERE, только в HAVING; ROWNUM назначается до сортировки.

## ? Чем WHERE отличается от HAVING?

WHERE фильтрует отдельные строки до группировки, агрегатные функции в нём запрещены. HAVING фильтрует уже готовые группы после GROUP BY, в нём можно использовать агрегаты (`HAVING COUNT(*) > 5`). Условия без агрегатов лучше писать в WHERE — меньше строк пойдёт в группировку.

## ? Чем COUNT(*) отличается от COUNT(столбец) и COUNT(DISTINCT столбец)?

`COUNT(*)` — количество строк, включая строки, где все значения NULL. `COUNT(col)` — количество строк, где `col` не NULL. `COUNT(DISTINCT col)` — количество разных непустых значений. `COUNT(1)` работает ровно как `COUNT(*)`, быстрее он не становится.

## ? Почему нельзя использовать алиас столбца в WHERE?

Потому что WHERE логически выполняется раньше SELECT: на момент фильтрации алиаса ещё нет — ORA-00904 invalid identifier. Варианты: повторить выражение в WHERE или обернуть запрос в подзапрос (inline view) и фильтровать по алиасу снаружи. В ORDER BY алиас можно.

## ? Что вернёт AVG по столбцу с NULL?

Среднее только по непустым значениям: NULL не участвуют ни в сумме, ни в количестве. Если у 3 из 20 сотрудников комиссия 0.1, 0.2, 0.3, то `AVG(commission_pct)` = 0.2, а не 0.03. Чтобы считать NULL как ноль — `AVG(NVL(commission_pct, 0))`.

## ? Что делают ROLLUP и CUBE?

Расширения GROUP BY для итогов. `GROUP BY ROLLUP(dept, job)` даёт строки по (dept, job), итоги по каждому dept и общий итог. `CUBE(dept, job)` — итоги по всем комбинациям: ещё и по каждому job отдельно. В строках итогов «свёрнутые» столбцы равны NULL; отличить их от настоящих NULL помогает `GROUPING(col)`.

## Тест: Какой запрос вызовет ошибку?
- SELECT salary*12 AS y FROM employees ORDER BY y
- [x] SELECT salary*12 AS y FROM employees WHERE y > 100000
- SELECT salary*12 AS y FROM employees WHERE salary*12 > 100000
- SELECT * FROM (SELECT salary*12 AS y FROM employees) WHERE y > 100000
> WHERE выполняется до SELECT, поэтому алиаса `y` там ещё нет — ORA-00904. В ORDER BY и во внешнем запросе алиас уже существует.

## Тест: Где можно написать условие AVG(salary) > 8000?
- В WHERE
- [x] В HAVING
- В GROUP BY
- В ORDER BY только через алиас
> Агрегат вычисляется по группе, а группы появляются после GROUP BY. Фильтр по группам — HAVING.

## Тест: В таблице 20 сотрудников, commission_pct заполнен у 3. Что вернут COUNT(*) и COUNT(commission_pct)?
- 20 и 20
- [x] 20 и 3
- 3 и 3
- 20 и 17
> `COUNT(*)` считает строки, `COUNT(столбец)` — только строки с непустым значением.

## Тест: Чем закончится запрос SELECT department_id, job_id, COUNT(*) FROM employees GROUP BY department_id?
- Вернёт первую должность каждого отдела
- Вернёт строку на каждую пару отдел–должность
- [x] Ошибка ORA-00979: not a GROUP BY expression
- Вернёт job_id = NULL
> `job_id` не в GROUP BY и не внутри агрегата. Каждый отдел — одна строка, а должностей в отделе несколько, Oracle не выбирает за тебя.

## Тест: Что вернёт SELECT SUM(salary) FROM employees WHERE 1 = 0?
- Ноль строк
- Одну строку со значением 0
- [x] Одну строку со значением NULL
- Ошибку NO_DATA_FOUND
> Агрегат без GROUP BY всегда даёт одну строку. Сумма по пустому набору — NULL (а `COUNT(*)` дал бы 0). Отсюда привычка писать `NVL(SUM(x), 0)`.

## Тест: Почему WHERE ROWNUM <= 3 ORDER BY salary DESC не даёт трёх самых высоких зарплат?
- ROWNUM работает только с ASC
- [x] ROWNUM назначается до сортировки — отбираются 3 произвольные строки, потом сортируются
- ORDER BY игнорируется при ROWNUM
- Нужно писать ROWNUM < 3
> ROWNUM нумерует строки по мере прохождения WHERE, сортировка — позже. Правильно: `ORDER BY salary DESC FETCH FIRST 3 ROWS ONLY` или сортировка во вложенном запросе.

## Тест: Что добавляет GROUP BY ROLLUP(department_id) по сравнению с обычным GROUP BY department_id?
- Сортировку по отделу
- Строки по каждому сотруднику
- [x] Строку общего итога
- Итоги по каждой комбинации всех столбцов
> ROLLUP по одному столбцу даёт обычные группы плюс строку итога со значением NULL в department_id. Итоги по всем комбинациям — это CUBE.
