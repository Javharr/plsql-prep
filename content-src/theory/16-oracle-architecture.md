## Экземпляр и база данных

В Oracle это **разные вещи**:

- **База данных** (database) — файлы на диске: файлы данных, управляющие файлы (control files), журналы повторного выполнения (redo logs).
- **Экземпляр** (instance) — то, что работает в памяти: области памяти (SGA) и фоновые процессы. Экземпляр открывает базу и обслуживает запросы.

Обычно один экземпляр на одну базу. В **RAC** (Real Application Clusters) несколько экземпляров на разных серверах работают с одной базой — для отказоустойчивости и масштабирования.

С 12c появилась **мультиарендная архитектура**: контейнерная база (CDB) и подключаемые базы (PDB) внутри неё. В Oracle 23ai Free ты подключаешься как раз к PDB `FREEPDB1`.

## Память: SGA и PGA

**SGA** (System Global Area) — общая память экземпляра для всех сессий:

| Часть | Что хранит |
|---|---|
| **Buffer cache** | блоки данных, прочитанные с диска; повторное чтение — из памяти |
| **Shared pool** | разобранные SQL и PL/SQL (library cache), словарь данных (dictionary cache) |
| **Redo log buffer** | изменения перед записью в redo-файлы |
| Large pool, Java pool | для отдельных задач: параллельные операции, RMAN, Java |

**PGA** (Program Global Area) — частная память **одного серверного процесса**: сортировки, хеш-соединения, переменные PL/SQL, курсоры. Если сортировке не хватает PGA — она уходит на диск во временное табличное пространство (медленно).

## Фоновые процессы

| Процесс | Задача |
|---|---|
| **DBWn** (database writer) | пишет изменённые («грязные») блоки из buffer cache в файлы данных — не при COMMIT, а когда нужно |
| **LGWR** (log writer) | пишет redo buffer в redo-файлы; COMMIT ждёт именно его |
| **CKPT** (checkpoint) | отмечает контрольные точки в файлах |
| **SMON** (system monitor) | восстановление экземпляра после сбоя, чистка временных сегментов |
| **PMON** (process monitor) | убирает за упавшими сессиями: откатывает их транзакции, снимает блокировки |
| **ARCn** (archiver) | копирует заполненные redo-файлы в архив (режим ARCHIVELOG) |

## Логическая структура хранения

**Табличное пространство** (tablespace) → **сегмент** (таблица, индекс) → **экстент** (непрерывный кусок) → **блок** (обычно 8 КБ — минимальная единица чтения и записи).

Табличное пространство состоит из одного или нескольких файлов данных. Стандартные: `SYSTEM`, `SYSAUX` — словарь; `UNDOTBS` — undo; `TEMP` — сортировки и временные данные; `USERS` — данные пользователей.

## Пользователь и схема

**Схема** — набор объектов (таблицы, представления, процедуры), принадлежащих пользователю. В Oracle пользователь и схема создаются вместе и имеют одно имя: создал пользователя `HR` — получил схему `HR`. Обращаться к чужим объектам — `hr.employees` (нужны права) или через синоним.

Права бывают **системные** (`CREATE TABLE`, `CREATE SESSION`) и **объектные** (`SELECT ON hr.employees`, `EXECUTE ON pkg`). Их группируют в **роли**.

> **Ловушка для PL/SQL:** права, полученные через **роль**, не действуют внутри процедур с правами создателя (definer rights) — там нужен прямой GRANT на объект. Иначе процедура не скомпилируется с ORA-00942 / PLS-00201, хотя тот же SELECT вне процедуры работает.

## Как выполняется SQL-запрос

1. **Разбор (parse):** проверка синтаксиса и прав, поиск такого же запроса в shared pool.
   - Нашёлся готовый план — **soft parse** (быстро).
   - Не нашёлся — **hard parse**: оптимизатор строит план (дорого по CPU и блокировкам shared pool).
2. **Привязка (bind):** подставляются значения bind-переменных.
3. **Выполнение (execute):** чтение блоков — сначала из buffer cache, при промахе с диска.
4. **Выборка (fetch):** строки отдаются клиенту порциями.

Отсюда важность **bind-переменных**: `WHERE id = :id` — один и тот же текст запроса, один разбор на все значения. `WHERE id = 101`, `WHERE id = 102`, … — каждый раз новый текст и hard parse.

## ? Чем экземпляр Oracle отличается от базы данных?

База данных — файлы на диске: данные, управляющие файлы, redo-журналы. Экземпляр — память (SGA) и фоновые процессы, которые эти файлы открывают и обслуживают. Обычно один экземпляр на базу; в RAC несколько экземпляров работают с одной базой.

## ? Что такое SGA и PGA?

SGA — общая память экземпляра: buffer cache (блоки данных), shared pool (разобранные SQL и PL/SQL, словарь), redo log buffer. PGA — частная память серверного процесса одной сессии: сортировки, хеш-соединения, переменные PL/SQL. Не хватило PGA на сортировку — работа уходит в TEMP на диск.

## ? Что происходит при COMMIT? Записываются ли данные в файлы?

LGWR записывает содержимое redo buffer в redo-файлы, и только после этого COMMIT возвращает управление. Сами изменённые блоки данных в файлы при COMMIT не пишутся — их позже сбросит DBWn. Это безопасно: после сбоя изменения восстановятся из redo.

## ? Чем схема отличается от пользователя?

Пользователь — учётная запись для подключения с правами. Схема — набор объектов, которыми он владеет. В Oracle они создаются вместе и называются одинаково, поэтому часто говорят как о синонимах. Бывают пользователи без объектов (только для подключения) — их схема пустая.

## ? Что такое hard parse и soft parse?

Hard parse — полный разбор нового запроса: проверка, построение плана оптимизатором, загрузка в shared pool. Дорого. Soft parse — такой же текст уже есть в shared pool, план переиспользуется. Чтобы разборов было меньше, используют bind-переменные вместо литералов: один текст запроса для всех значений.

## ? Какие фоновые процессы Oracle ты знаешь?

DBWn пишет изменённые блоки на диск, LGWR пишет redo (COMMIT ждёт его), CKPT отмечает контрольные точки, SMON восстанавливает экземпляр после сбоя, PMON убирает за упавшими сессиями (откатывает и снимает блокировки), ARCn архивирует redo-журналы.

## Тест: Что из этого относится к экземпляру (instance), а не к базе данных?
- Файлы данных
- Управляющие файлы
- [x] SGA и фоновые процессы
- Redo-журналы на диске
> Экземпляр — это память и процессы. Файлы на диске — это база данных.

## Тест: Где хранятся разобранные SQL-запросы и их планы для повторного использования?
- В buffer cache
- [x] В shared pool (library cache)
- В PGA
- В табличном пространстве TEMP
> Library cache в shared pool. Buffer cache хранит блоки данных, PGA — частная память сессии.

## Тест: Чего ждёт COMMIT перед тем, как вернуть управление?
- Записи изменённых блоков в файлы данных (DBWn)
- [x] Записи redo в журнал (LGWR)
- Контрольной точки (CKPT)
- Архивации журнала (ARCn)
> Долговечность обеспечивает redo: как только запись об изменении на диске, транзакция зафиксирована. Блоки данных DBWn сбросит позже.

## Тест: Какой процесс откатывает транзакцию и снимает блокировки, если клиентская сессия внезапно оборвалась?
- SMON
- [x] PMON
- LGWR
- DBWn
> PMON (process monitor) убирает за упавшими процессами. SMON отвечает за восстановление экземпляра целиком после его сбоя.

## Тест: Минимальная единица чтения и записи Oracle — это…
- Строка
- [x] Блок
- Экстент
- Сегмент
> Oracle читает и пишет блоками (обычно 8 КБ). Экстент — группа блоков, сегмент — набор экстентов объекта.

## Тест: Пользователь получил SELECT на hr.employees через роль. Процедура с правами создателя, читающая hr.employees, не компилируется. Почему?
- Роли не дают SELECT
- [x] Внутри definer-rights PL/SQL права через роли не действуют — нужен прямой GRANT
- Нужно перезапустить базу
- Процедуры не могут читать чужие таблицы
> При компиляции и выполнении процедур с правами создателя учитываются только права, выданные напрямую. Прямой `GRANT SELECT ON hr.employees TO user` решает проблему.

## Тест: Почему запросы с bind-переменными (WHERE id = :id) нагружают сервер меньше, чем с литералами?
- Bind-переменные быстрее читаются с диска
- [x] Один текст запроса — один hard parse, дальше план переиспользуется
- Bind-переменные кешируют результат запроса
- Они не требуют проверки прав
> Литералы делают каждый запрос уникальным текстом и вызывают hard parse. С bind-переменными shared pool не забивается и CPU не тратится на разбор.
