## Что такое пакет

**Пакет** — контейнер, объединяющий связанные процедуры, функции, типы, переменные, константы, курсоры и исключения. Состоит из двух частей, которые создаются и компилируются отдельно:

- **Спецификация** (`CREATE PACKAGE`) — публичный интерфейс: то, что видно снаружи.
- **Тело** (`CREATE PACKAGE BODY`) — реализация объявленного в спецификации плюс приватные элементы.

```sql
CREATE OR REPLACE PACKAGE emp_api IS
  c_max_raise CONSTANT NUMBER := 30;
  e_bad_raise EXCEPTION;
  PROCEDURE raise_salary (p_emp_id NUMBER, p_pct NUMBER);
  FUNCTION  annual_salary (p_emp_id NUMBER) RETURN NUMBER;
END emp_api;
/

CREATE OR REPLACE PACKAGE BODY emp_api IS
  -- приватная: не объявлена в спецификации, снаружи не видна
  PROCEDURE check_pct (p_pct NUMBER) IS
  BEGIN
    IF p_pct > c_max_raise THEN RAISE e_bad_raise; END IF;
  END;

  PROCEDURE raise_salary (p_emp_id NUMBER, p_pct NUMBER) IS
  BEGIN
    check_pct(p_pct);
    UPDATE employees SET salary = salary * (1 + p_pct / 100) WHERE employee_id = p_emp_id;
  END;

  FUNCTION annual_salary (p_emp_id NUMBER) RETURN NUMBER IS
    v NUMBER;
  BEGIN
    SELECT salary * 12 INTO v FROM employees WHERE employee_id = p_emp_id;
    RETURN v;
  END;
END emp_api;
/
```

Вызов: `emp_api.raise_salary(100, 5);`, `emp_api.c_max_raise`.

## Зачем пакеты

1. **Инкапсуляция:** наружу — только интерфейс, вспомогательный код скрыт в теле.
2. **Меньше каскадных перекомпиляций:** зависимые объекты зависят от спецификации. Поменял только тело — вызывающий код **не становится INVALID**. С отдельными процедурами любое изменение задевает всех.
3. **Организация:** всё про сотрудников — в `emp_api`, а не 40 разрозненных процедур.
4. **Перегрузка:** несколько подпрограмм с одним именем и разными параметрами.
5. **Состояние в сессии:** переменные уровня пакета живут всю сессию.
6. **Производительность:** при первом обращении пакет загружается в память целиком.
7. **Права:** `GRANT EXECUTE` на пакет одной командой.

Спецификация может существовать без тела, если в ней только типы, константы и исключения.

## Состояние пакета

Переменные, объявленные на уровне пакета (в спецификации или вне подпрограмм в теле), **сохраняют значения между вызовами в течение сессии**. Каждая сессия имеет **свою** копию — это не общая память между пользователями.

```sql
CREATE OR REPLACE PACKAGE counter IS
  g_calls NUMBER := 0;
  PROCEDURE hit;
END;
```

Применение: кэш справочника в памяти сессии, настройки, накопление данных между вызовами триггеров (в compound trigger это делается проще).

`PRAGMA SERIALLY_REUSABLE` — состояние сбрасывается после каждого вызова к серверу (экономия памяти).

## ORA-04068: existing state of packages has been discarded

Если пакет с состоянием перекомпилировали (например, выкатили новую версию), то у всех сессий, где он уже был загружен, при следующем вызове возникнет:

`ORA-04068: existing state of packages has been discarded` (вместе с ORA-04061 / ORA-04065).

Состояние сброшено, повторный вызов уже сработает. Как избегать: не держать состояние в пакетах без необходимости (пакет без переменных уровня пакета этой ошибки не даёт), выносить состояние в отдельный пакет, использовать Edition-Based Redefinition для обновлений без простоя.

## Инициализация и перегрузка

**Секция инициализации** — блок `BEGIN … END` в самом конце тела. Выполняется **один раз за сессию**, при первом обращении к пакету:

```sql
CREATE OR REPLACE PACKAGE BODY settings IS
  g_tax NUMBER;
  FUNCTION tax RETURN NUMBER IS BEGIN RETURN g_tax; END;
BEGIN
  SELECT rate INTO g_tax FROM config WHERE key = 'TAX';   -- загрузить один раз
END settings;
```

**Перегрузка** — несколько подпрограмм с одним именем, различающихся количеством, порядком или **семействами** типов параметров:

```sql
PROCEDURE log_it (p_msg VARCHAR2);
PROCEDURE log_it (p_code NUMBER, p_msg VARCHAR2);
```

Нельзя перегрузить, если отличаются только режимы параметров (IN/OUT), только тип возвращаемого значения функции или типы из одного семейства (`NUMBER` и `INTEGER`).

Порядок объявления: приватная подпрограмма в теле должна быть объявлена **до** использования, иначе — **предварительное объявление** (forward declaration).

## Встроенные пакеты Oracle

| Пакет | Для чего |
|---|---|
| `DBMS_OUTPUT` | вывод отладочного текста (`PUT_LINE`) |
| `DBMS_SQL` | динамический SQL с неизвестным заранее набором столбцов и параметров |
| `DBMS_SCHEDULER` | задания по расписанию (замена `DBMS_JOB`) |
| `DBMS_LOB` | работа с CLOB/BLOB |
| `DBMS_UTILITY` | `FORMAT_ERROR_BACKTRACE`, `COMPILE_SCHEMA`, замер времени `GET_TIME` |
| `DBMS_STATS` | сбор статистики для оптимизатора |
| `DBMS_XPLAN` | вывод планов выполнения |
| `UTL_FILE` | чтение и запись файлов на сервере |
| `DBMS_LOCK` / `DBMS_SESSION` | пользовательские блокировки, `SLEEP` |
| `DBMS_ASSERT` | проверка имён для защиты от SQL-инъекций |
| `UTL_HTTP`, `UTL_MAIL` | HTTP-запросы и почта из базы |

## ? Из каких частей состоит пакет и зачем их разделять?

Спецификация — публичный интерфейс: объявления процедур, функций, типов, констант, исключений, видимые снаружи. Тело — реализация и приватные элементы. Разделение даёт инкапсуляцию и позволяет менять тело, не инвалидируя зависимые объекты: они зависят только от спецификации.

## ? Какие преимущества у пакетов перед отдельными процедурами?

Инкапсуляция (приватный код в теле), меньше каскадных перекомпиляций при изменении реализации, логическая группировка, перегрузка, состояние уровня сессии, загрузка в память целиком при первом обращении, выдача прав одной командой.

## ? Что такое состояние пакета? Видят ли его другие сессии?

Переменные уровня пакета сохраняют значения между вызовами в течение сессии. У каждой сессии своя копия — другие сессии их не видят. Для общих между сессиями данных нужны таблицы или контексты приложения (глобальные).

## ? Что означает ORA-04068 и как её избежать?

Существующее состояние пакета сброшено: пакет с переменными уровня пакета перекомпилировали, пока сессия его использовала. Повторный вызов работает. Избежать: не хранить состояние в пакетах без нужды (пакеты без состояния этой ошибки не дают), выносить состояние в отдельный пакет, использовать Edition-Based Redefinition.

## ? Что такое секция инициализации пакета?

Блок BEGIN в конце тела пакета, который выполняется один раз за сессию при первом обращении к любому элементу пакета. Используется для загрузки настроек или кэша. Необработанное исключение из неё вылетит в тот код, который первым обратился к пакету, причём с непонятным для него текстом, — поэтому ошибки инициализации стоит обрабатывать и превращать в ясное сообщение.

## ? Что такое перегрузка и какие у неё ограничения?

Несколько подпрограмм с одним именем в пакете, различающихся количеством, порядком или семейством типов параметров. Нельзя перегрузить, если отличаются только режимы параметров, только тип результата функции или типы одного семейства (NUMBER и INTEGER, VARCHAR2 и CHAR — неоднозначно при вызове).

## ? Какие встроенные пакеты Oracle ты использовал?

DBMS_OUTPUT — отладочный вывод; DBMS_SCHEDULER — задания по расписанию; DBMS_SQL — сложный динамический SQL; DBMS_UTILITY — backtrace ошибок и перекомпиляция; DBMS_STATS — статистика; DBMS_XPLAN — планы; DBMS_LOB — большие объекты; UTL_FILE — файлы на сервере; DBMS_ASSERT — защита от SQL-инъекций.

## Тест: Что означает ORA-04068 existing state of packages has been discarded?
- Пакет удалён
- В пакете синтаксическая ошибка
- [x] Пакет с состоянием перекомпилировали, и состояние в текущей сессии сброшено

> Повторный вызов отработает. Пакеты без переменных уровня пакета этой ошибки не вызывают.

## Тест: Какие две процедуры НЕЛЬЗЯ перегрузить в одном пакете?
