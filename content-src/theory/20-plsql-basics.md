## Что такое PL/SQL

**PL/SQL** (Procedural Language extensions to SQL) — процедурный язык Oracle, встроенный в базу. SQL отвечает на вопрос «какие данные», а PL/SQL добавляет то, чего в SQL нет: переменные, условия, циклы, обработку ошибок, процедуры, функции, пакеты, триггеры.

Код выполняется **внутри сервера базы**, рядом с данными. Отсюда главные плюсы:

- меньше сетевых обменов: одна вызванная процедура делает десятки SQL-команд на сервере;
- бизнес-логика и правила целостности в одном месте для всех приложений;
- безопасность: приложению дают право `EXECUTE` на процедуру, а не на таблицы.

## Структура блока

```sql
DECLARE                          -- необязательно: объявления
  v_name  employees.last_name%TYPE;
  v_count PLS_INTEGER := 0;
  c_limit CONSTANT NUMBER := 100;
BEGIN                            -- обязательно: исполняемая часть
  SELECT last_name INTO v_name FROM employees WHERE employee_id = 100;
  DBMS_OUTPUT.PUT_LINE('Имя: ' || v_name);
EXCEPTION                        -- необязательно: обработка ошибок
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('Нет такого сотрудника');
END;
/
```

Минимальный блок — `BEGIN NULL; END;`. Блоки можно вкладывать: у вложенного блока свои переменные и свой раздел EXCEPTION.

- **Анонимный блок** — без имени, не хранится в базе, выполняется один раз (скрипт, тест).
- **Именованный блок** — процедура, функция, пакет, триггер: компилируется и хранится в базе.

## Переменные, %TYPE и %ROWTYPE

- Присваивание — `:=`, одиночное `=` — только сравнение.
- Переменная без начального значения равна `NULL`.
- `CONSTANT` — значение задаётся один раз при объявлении.
- `NOT NULL` — переменная обязана иметь значение (нужно начальное).
- Тип `BOOLEAN` (TRUE/FALSE/NULL) — до Oracle 23ai существовал только в PL/SQL, не в SQL-таблицах.

**`%TYPE`** — взять тип столбца или другой переменной: `v_sal employees.salary%TYPE`. Если тип столбца поменяют (`NUMBER(8,2)` → `NUMBER(10,2)`), код не придётся править.

**`%ROWTYPE`** — запись со всеми столбцами таблицы или курсора:

```sql
DECLARE
  r employees%ROWTYPE;
BEGIN
  SELECT * INTO r FROM employees WHERE employee_id = 100;
  DBMS_OUTPUT.PUT_LINE(r.first_name || ' ' || r.last_name || ': ' || r.salary);
END;
```

## SELECT INTO и его исключения

`SELECT … INTO` кладёт результат запроса в переменные. Требование — **ровно одна строка**:

| Строк вернулось | Что будет |
|---|---|
| 0 | исключение `NO_DATA_FOUND` (ORA-01403) |
| 1 | значения в переменных |
| больше 1 | исключение `TOO_MANY_ROWS` (ORA-01422) |

Для нескольких строк — курсор или `BULK COLLECT INTO` коллекция. Агрегат без GROUP BY (`SELECT COUNT(*) INTO …`) всегда возвращает одну строку, поэтому NO_DATA_FOUND не бросает.

## Условия и циклы

```sql
IF v_sal > 10000 THEN … ELSIF v_sal > 5000 THEN … ELSE … END IF;   -- ELSIF, без второй E

CASE v_grade WHEN 'A' THEN … WHEN 'B' THEN … ELSE … END CASE;
```

Если в CASE-**операторе** ни одна ветка не подошла и нет ELSE — исключение `CASE_NOT_FOUND`. (CASE-**выражение** в такой ситуации вернёт NULL.)

Циклы:

```sql
LOOP … EXIT WHEN условие; END LOOP;            -- простой, выход по условию
WHILE условие LOOP … END LOOP;                  -- проверка до итерации
FOR i IN 1..10 LOOP … END LOOP;                 -- счётчик, i объявлять не нужно
FOR i IN REVERSE 1..10 LOOP … END LOOP;         -- от 10 до 1
FOR r IN (SELECT … FROM …) LOOP … END LOOP;     -- курсорный цикл
```

`CONTINUE` / `CONTINUE WHEN` — перейти к следующей итерации. Счётчик FOR-цикла доступен только внутри цикла и только для чтения. Если нижняя граница больше верхней — цикл не выполнится ни разу.

## Переключение контекста SQL ↔ PL/SQL

В Oracle два движка: **PL/SQL-движок** выполняет процедурный код, **SQL-движок** — SQL-команды. Каждый SQL внутри PL/SQL — это передача управления между ними (**context switch**), и у неё есть цена.

Поэтому построчная обработка «курсор → цикл → UPDATE по одной строке» медленная: на каждую строку — переключение. Правила:

1. Что можно сделать **одной SQL-командой** — делай одной командой (`UPDATE … WHERE …`, `INSERT … SELECT`, `MERGE`).
2. Если нужна процедурная обработка — пакетно: `BULK COLLECT` и `FORALL` (одно переключение на тысячи строк).
3. Функции PL/SQL, вызванные в SQL на каждую строку, тоже переключают контекст — помогают `PRAGMA UDF`, `DETERMINISTIC`, кэширование.

## ? Что такое PL/SQL и чем он отличается от SQL?

SQL — декларативный язык запросов: описываешь, какие данные нужны. PL/SQL — процедурное расширение Oracle: переменные, условия, циклы, исключения, процедуры, функции, пакеты, триггеры. PL/SQL выполняется на сервере базы рядом с данными и сам использует SQL внутри. Плюсы: меньше сетевых обменов, логика в одном месте, контроль доступа через EXECUTE.

## ? Из каких частей состоит PL/SQL-блок?

DECLARE — объявления переменных, констант, курсоров, типов (необязательная). BEGIN … END — исполняемая часть (обязательная). EXCEPTION — обработчики ошибок (необязательная). Блоки бывают анонимными (не хранятся) и именованными (процедуры, функции, пакеты, триггеры), их можно вкладывать.

## ? Зачем нужны %TYPE и %ROWTYPE?

%TYPE объявляет переменную с типом столбца или другой переменной, %ROWTYPE — запись со структурой строки таблицы или курсора. Код не зависит от точного типа: изменили длину столбца — переменные подстроятся сами после перекомпиляции, и не будет VALUE_ERROR.

## ? Что будет, если SELECT INTO вернёт 0 строк или больше одной?

0 строк — исключение NO_DATA_FOUND, больше одной — TOO_MANY_ROWS. Поэтому SELECT INTO используют, когда строка гарантированно одна (поиск по ключу), и обрабатывают NO_DATA_FOUND. Исключение — агрегат без GROUP BY: всегда одна строка, даже если данных нет.

## ? Что такое переключение контекста и как его уменьшить?

В Oracle SQL и PL/SQL выполняются разными движками; каждый SQL из PL/SQL и каждый вызов PL/SQL-функции из SQL — передача управления с накладными расходами. Уменьшить: делать работу одной SQL-командой вместо цикла, использовать BULK COLLECT и FORALL, кэшировать результаты функций, вызываемых из SQL (DETERMINISTIC, RESULT_CACHE, PRAGMA UDF).

## ? Какие виды циклов есть в PL/SQL?

Простой LOOP с EXIT WHEN, WHILE (условие проверяется до итерации), числовой FOR i IN a..b (и REVERSE), курсорный FOR r IN (SELECT …). Плюс CONTINUE для перехода к следующей итерации. Для обработки данных лучше курсорный FOR или BULK COLLECT, а не ручной перебор.
