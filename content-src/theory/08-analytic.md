## Чем аналитика отличается от GROUP BY

Агрегат с `GROUP BY` **схлопывает** строки: из группы получается одна строка. Аналитическая функция считает значение по группе строк («окну»), но **оставляет каждую строку** на месте:

```sql
SELECT last_name, department_id, salary,
       AVG(salary) OVER (PARTITION BY department_id) AS dept_avg
  FROM employees;
```

У каждого сотрудника — его зарплата и рядом средняя по его отделу. С GROUP BY пришлось бы соединять таблицу с подзапросом.

Аналитические функции вычисляются **после** WHERE, GROUP BY и HAVING, прямо перед ORDER BY. Поэтому их **нельзя использовать в WHERE** — фильтровать по ним можно только во внешнем запросе.

## Анатомия OVER (…)

```sql
функция(...) OVER (
  PARTITION BY ...   -- на какие группы делить (как GROUP BY, но без схлопывания)
  ORDER BY ...       -- порядок внутри группы (нужен для рангов, LAG/LEAD, нарастающих итогов)
  ROWS | RANGE BETWEEN ... AND ...   -- рамка: какие строки окна брать для текущей
)
```

- Без `PARTITION BY` окно — весь результат.
- Пустые скобки `OVER ()` — одно окно на всё, например доля от общей суммы: `salary / SUM(salary) OVER ()`.

## Ранжирование: ROW_NUMBER, RANK, DENSE_RANK

Разница — в обработке одинаковых значений. Зарплаты 9000, 8000, 8000, 7000 по убыванию:

| salary | ROW_NUMBER | RANK | DENSE_RANK |
|---|---|---|---|
| 9000 | 1 | 1 | 1 |
| 8000 | 2 | 2 | 2 |
| 8000 | 3 | 2 | 2 |
| 7000 | 4 | **4** | **3** |

- `ROW_NUMBER` — всегда уникальный номер; среди равных порядок произвольный (добавь в ORDER BY уникальный столбец, чтобы он был стабильным).
- `RANK` — равные получают одинаковый ранг, следующий ранг **с пропуском**.
- `DENSE_RANK` — без пропусков.

Ещё: `NTILE(4)` делит строки на 4 примерно равные группы (квартили), `PERCENT_RANK`, `CUME_DIST` — относительное положение.

## Топ-N в каждой группе

Классическая задача: «два самых высокооплачиваемых сотрудника в каждом отделе».

```sql
SELECT *
  FROM (SELECT e.*,
               DENSE_RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rn
          FROM employees e)
 WHERE rn <= 2;
```

Выбор функции — это вопрос требований: `ROW_NUMBER` даст ровно 2 строки, `DENSE_RANK` — все, у кого одна из двух наибольших зарплат (может быть больше двух людей). Фильтр — во внешнем запросе, потому что в WHERE аналитика запрещена.

## LAG, LEAD, FIRST_VALUE

Доступ к соседним строкам окна без self-join:

```sql
SELECT employee_id, hire_date, salary,
       LAG(salary)  OVER (ORDER BY hire_date) AS prev_salary,   -- предыдущая строка
       LEAD(salary) OVER (ORDER BY hire_date) AS next_salary,   -- следующая
       salary - LAG(salary, 1, 0) OVER (ORDER BY hire_date) AS diff  -- со значением по умолчанию
  FROM employees;
```

`FIRST_VALUE(x) OVER (…)` и `LAST_VALUE(x) OVER (…)` — первое и последнее значение в рамке. Типичная ловушка — `LAST_VALUE` с `ORDER BY` без явной рамки возвращает значение **текущей** строки (см. ниже).

## Рамка окна и нарастающий итог

Если в `OVER` есть `ORDER BY`, но нет явной рамки, по умолчанию действует `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` — от начала окна до текущей строки (включая строки с тем же значением ключа сортировки). Так получается **нарастающий итог**:

```sql
SELECT hire_date, salary,
       SUM(salary) OVER (ORDER BY hire_date) AS running_total,
       AVG(salary) OVER (ORDER BY hire_date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS moving_avg3
  FROM employees;
```

- `ROWS` — рамка в **строках** (ровно 2 предыдущих).
- `RANGE` — рамка по **значениям** ключа: строки с одинаковой датой попадут в окно вместе. Поэтому при дублях `SUM … ORDER BY hire_date` прибавляет сразу всех нанятых в один день.
- Для `LAST_VALUE` по всему окну нужна явная рамка: `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`.

## ? Чем аналитические функции отличаются от агрегатных с GROUP BY?

GROUP BY схлопывает группу в одну строку. Аналитическая функция считает по окну, но возвращает значение для каждой строки, не уменьшая их число. Поэтому можно в одном запросе показать сотрудника, его зарплату и среднюю по отделу. Аналитика вычисляется после WHERE/GROUP BY/HAVING, фильтровать по ней можно только во внешнем запросе.

## ? Чем отличаются ROW_NUMBER, RANK и DENSE_RANK?

На одинаковых значениях. ROW_NUMBER всегда даёт уникальные номера 1, 2, 3, 4. RANK даёт равным одинаковый ранг и пропускает следующие: 1, 2, 2, 4. DENSE_RANK — без пропусков: 1, 2, 2, 3. Для «топ-N в группе» выбор зависит от того, нужно ли ровно N строк или все, кто делит место.

## ? Как найти вторую по величине зарплату в каждом отделе?

`DENSE_RANK() OVER (PARTITION BY department_id ORDER BY salary DESC)` во вложенном запросе и `WHERE rn = 2` снаружи. DENSE_RANK — чтобы при одинаковых максимальных зарплатах «второй» была следующая по величине зарплата, а не вторая строка.

## ? Почему нельзя написать ROW_NUMBER() OVER (…) в WHERE?

Аналитические функции вычисляются на этапе SELECT — после WHERE, GROUP BY и HAVING. На момент фильтрации их значений ещё нет (ORA-30483). Решение — inline view или WITH, а фильтр снаружи.

## ? Что делают LAG и LEAD?

Возвращают значение из предыдущей (LAG) или следующей (LEAD) строки окна в заданном порядке: `LAG(salary, 1, 0) OVER (PARTITION BY dept ORDER BY hire_date)` — зарплата предыдущего нанятого в отделе или 0, если его нет. Заменяют self-join для сравнения с соседней строкой: разница с прошлым месяцем, интервал между событиями.

## ? Как посчитать нарастающий итог?

`SUM(amount) OVER (ORDER BY dt)` — по умолчанию рамка от начала окна до текущей строки. Для итога внутри групп — добавить `PARTITION BY`. Если в ключе сортировки есть дубли, а нужно строго построчно, — указать `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` и уникальный ORDER BY.

## Тест: LAST_VALUE(salary) OVER (ORDER BY hire_date) возвращает не последнюю зарплату, а зарплату текущей строки. Почему?
- LAST_VALUE работает только с PARTITION BY
- [x] Рамка по умолчанию заканчивается на текущей строке
- Нужно ORDER BY hire_date DESC
- Это ошибка Oracle
> С ORDER BY рамка по умолчанию — от начала до текущей строки, значит «последняя в рамке» — текущая. Нужна явная рамка `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`.
