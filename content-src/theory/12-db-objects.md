## Представление (VIEW)

Представление — **сохранённый запрос** с именем. Данных само не хранит: при обращении Oracle подставляет его текст в твой запрос.

```sql
CREATE OR REPLACE VIEW emp_dept_v AS
SELECT e.employee_id, e.last_name, d.department_name
  FROM employees e JOIN departments d ON d.department_id = e.department_id;
```

Зачем:

- **упростить** сложные запросы: соединения и вычисления пишутся один раз;
- **безопасность**: дать доступ к представлению со столбцами без зарплат, а к таблице — нет;
- **стабильный интерфейс**: таблицы можно перестраивать, а представление оставить прежним.

Через простое представление (одна таблица, без агрегатов, DISTINCT, GROUP BY) можно делать DML. `WITH CHECK OPTION` запрещает вставлять и обновлять строки так, чтобы они «выпали» из представления. `WITH READ ONLY` запрещает DML. Для сложных представлений DML делают через триггер `INSTEAD OF`.

## Материализованное представление (MV)

В отличие от VIEW, **хранит результат** запроса физически, как таблица. Читается быстро, но данные могут устаревать — их нужно обновлять:

```sql
CREATE MATERIALIZED VIEW sales_by_month_mv
  REFRESH COMPLETE ON DEMAND
AS SELECT TRUNC(sale_date, 'MM') AS mon, SUM(amount) AS total
     FROM sales GROUP BY TRUNC(sale_date, 'MM');

EXEC DBMS_MVIEW.REFRESH('SALES_BY_MONTH_MV');
```

- `REFRESH COMPLETE` — пересчитать всё; `FAST` — применить только изменения (нужны MV-логи на исходных таблицах); `FORCE` — fast, если возможно.
- `ON DEMAND` — по команде или по расписанию; `ON COMMIT` — при каждом коммите в исходные таблицы.
- **Query rewrite** — оптимизатор может сам подставить MV в запрос к исходным таблицам.

Применяют для тяжёлых отчётных агрегатов и репликации данных.

## Последовательности и IDENTITY

**Последовательность** (SEQUENCE) — генератор уникальных чисел, независимый от таблиц:

```sql
CREATE SEQUENCE orders_seq START WITH 1 INCREMENT BY 1 CACHE 20;
INSERT INTO orders (order_id, ...) VALUES (orders_seq.NEXTVAL, ...);
SELECT orders_seq.CURRVAL FROM dual;   -- последнее значение, выданное ЭТОЙ сессии
```

Важное:

- **гарантирует уникальность, но не непрерывность**: пропуски нормальны — ROLLBACK не возвращает номер, а при перезапуске теряется кэш (`CACHE 20`);
- `CURRVAL` до первого `NEXTVAL` в сессии — ошибка ORA-08002;
- не зависит от транзакций: выданный номер не откатывается.

**IDENTITY** (12c+) — автоинкремент столбца, внутри — та же последовательность:

```sql
CREATE TABLE orders (order_id NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY, ...);
```

`ALWAYS` — вставить своё значение нельзя; `BY DEFAULT` — можно, если указать явно.

## Синонимы

Синоним — **другое имя** объекта. Позволяет обращаться к `hr.employees` просто как `employees`, не меняя код при переносе объекта в другую схему.

```sql
CREATE SYNONYM emp FOR hr.employees;           -- частный, в своей схеме
CREATE PUBLIC SYNONYM emp FOR hr.employees;    -- для всех пользователей
```

Синоним не даёт прав: доступ к самому объекту всё равно нужен через `GRANT`.

## Временные таблицы

**Глобальная временная таблица** (GTT): структура постоянная, а данные видит только своя сессия и живут они до конца транзакции или сессии.

```sql
CREATE GLOBAL TEMPORARY TABLE tmp_calc (id NUMBER, val NUMBER)
  ON COMMIT DELETE ROWS;        -- или PRESERVE ROWS: до конца сессии
```

Удобны для промежуточных результатов сложной обработки: нет конфликтов между сессиями, генерируется меньше redo. В 18c+ есть ещё **частные временные таблицы** (`ORA$PTT_…`), которые существуют только в памяти сессии.

## Секционирование (partitioning)

Большую таблицу физически делят на **секции** по ключу, логически она остаётся одной:

- `RANGE` — по диапазонам (месяцы, годы); `LIST` — по списку значений (регионы); `HASH` — равномерно по хешу; `INTERVAL` — новые секции по диапазону создаются сами.

Выгода: **partition pruning** — запрос с условием по ключу читает только нужные секции; старые данные удаляются мгновенно `ALTER TABLE … DROP PARTITION` вместо долгого DELETE; секции можно обслуживать по отдельности. Индексы бывают локальные (секционированы так же) и глобальные.

## ? Чем представление отличается от таблицы и от материализованного представления?

Таблица хранит данные. Представление — сохранённый запрос без данных: при каждом обращении выполняется заново, всегда актуально. Материализованное представление хранит результат запроса физически: читается быстро, но может устаревать и требует обновления (COMPLETE/FAST, ON DEMAND/ON COMMIT).

## ? Зачем нужны представления?

Упростить запросы (соединения и вычисления в одном месте), ограничить доступ (дать права на представление без чувствительных столбцов), сохранить интерфейс при изменении структуры таблиц. Через простые представления можно делать DML, через сложные — с INSTEAD OF-триггером.

## ? Гарантирует ли последовательность номера без пропусков?

Нет, только уникальность. Пропуски появляются при ROLLBACK (номер не возвращается), при потере кэша последовательности после рестарта, при параллельной работе нескольких сессий. Если нужна строгая нумерация без дыр (номера счетов) — это отдельная логика с блокировкой счётчика, и она снижает параллельность.

## ? Чем NEXTVAL отличается от CURRVAL?

NEXTVAL выдаёт следующее значение и увеличивает последовательность. CURRVAL возвращает последнее значение, выданное через NEXTVAL **в текущей сессии**; если в сессии NEXTVAL ещё не вызывали — ORA-08002. Значения других сессий CURRVAL не видит.

## ? Что такое синоним?

Альтернативное имя объекта (таблицы, представления, процедуры). Частный — в своей схеме, публичный (PUBLIC) — для всех. Позволяет не писать имя схемы и спрятать реальное расположение объекта. Прав не даёт — нужен отдельный GRANT на сам объект.

## ? Что такое глобальная временная таблица?

Таблица, структура которой постоянна, а данные видны только своей сессии и удаляются при COMMIT (ON COMMIT DELETE ROWS) или в конце сессии (PRESERVE ROWS). Используется для промежуточных данных: нет конфликтов между сессиями, меньше redo.

## ? Что даёт секционирование таблицы?

Partition pruning — запрос с условием по ключу секционирования читает только нужные секции. Быстрое удаление старых данных через DROP/TRUNCATE PARTITION вместо DELETE. Обслуживание по частям: перестроить индекс, сжать, перенести секцию. Для приложения таблица остаётся одной.

## Тест: Данные в GLOBAL TEMPORARY TABLE ... ON COMMIT DELETE ROWS видны…
