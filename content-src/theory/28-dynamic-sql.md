## Статический и динамический SQL

**Статический** SQL написан прямо в коде PL/SQL. Компилятор проверяет его при компиляции: таблицы существуют, столбцы правильные, права есть, и записывает зависимости.

**Динамический** SQL — текст команды собирается во время выполнения как строка. Нужен, когда:

- выполняются **DDL** и команды, которых нет в статическом PL/SQL (`CREATE`, `ALTER`, `TRUNCATE`, `GRANT`);
- имя таблицы, столбца или схемы известно только при выполнении;
- условие WHERE или список столбцов собирается из фильтров пользователя.

Цена: ошибки (опечатка в имени столбца) обнаруживаются только при выполнении, нет отслеживания зависимостей, код сложнее читать, и появляется риск SQL-инъекций.

## EXECUTE IMMEDIATE

```sql
-- DDL
EXECUTE IMMEDIATE 'TRUNCATE TABLE stage_orders';

-- DML с bind-переменными
EXECUTE IMMEDIATE 'UPDATE employees SET salary = salary * :pct WHERE department_id = :dept'
  USING 1.1, 60;
DBMS_OUTPUT.PUT_LINE(SQL%ROWCOUNT);

-- запрос одной строки
EXECUTE IMMEDIATE 'SELECT last_name FROM employees WHERE employee_id = :id'
  INTO v_name USING 100;

-- запрос многих строк
EXECUTE IMMEDIATE 'SELECT employee_id FROM ' || v_table
  BULK COLLECT INTO v_ids;

-- RETURNING
EXECUTE IMMEDIATE 'UPDATE employees SET salary = salary + 100 WHERE employee_id = :id RETURNING salary INTO :s'
  USING 100 RETURNING INTO v_new_sal;
```

Правила:

- В конце строки **не ставится** `;` для SQL-команды (будет ORA-00933/ORA-00911). Для PL/SQL-блока — наоборот, нужен `BEGIN … END;` с точкой с запятой.
- Bind-переменные связываются **по позиции**, а не по имени: `:a, :b, :a` требует три значения в USING (в SQL; в анонимном PL/SQL-блоке повторяющиеся имена связываются один раз).
- Bind-переменной можно передать **значение**, но **нельзя** передать имя таблицы, столбца, ключевое слово — их приходится вклеивать в текст.
- Нельзя передать NULL литералом в USING — нужна переменная со значением NULL.

## OPEN FOR и DBMS_SQL

**Курсорная переменная** для динамического многострочного запроса:

```sql
OPEN rc FOR 'SELECT employee_id, last_name FROM employees WHERE department_id = :d' USING p_dept;
```

**DBMS_SQL** — низкоуровневый пакет. Нужен, когда **заранее неизвестно** количество bind-переменных или **столбцов результата** (метод 4: универсальная выгрузка любой таблицы в CSV). Шаги: `OPEN_CURSOR` → `PARSE` → `BIND_VARIABLE` → `DEFINE_COLUMN` → `EXECUTE` → `FETCH_ROWS` → `COLUMN_VALUE` → `CLOSE_CURSOR`. `DESCRIBE_COLUMNS` возвращает описание столбцов. Курсор DBMS_SQL можно превратить в REF CURSOR (`TO_REFCURSOR`) и обратно.

Во всех остальных случаях хватает `EXECUTE IMMEDIATE` — он проще и быстрее.

## SQL-инъекция

Если вклеивать в текст запроса **данные пользователя**, он может изменить смысл команды:

```sql
-- уязвимо
v_sql := 'SELECT * FROM users WHERE login = ''' || p_login || '''';
```

При `p_login = x' OR '1'='1` запрос превратится в `… WHERE login = 'x' OR '1'='1'` и вернёт всех пользователей. Хуже — если код выполняется с правами владельца (DEFINER) и через инъекцию можно вызвать что-то опасное.

**Защита:**

1. **Bind-переменные для всех значений** — значение никогда не становится частью текста команды:
   `EXECUTE IMMEDIATE 'SELECT … WHERE login = :l' INTO … USING p_login;`
2. **Имена объектов** (их через bind не передать) — проверять:
   - `DBMS_ASSERT.SIMPLE_SQL_NAME(p_col)` — допустимое имя;
   - `DBMS_ASSERT.SQL_OBJECT_NAME(p_tab)` — существующий объект;
   - `DBMS_ASSERT.ENQUOTE_NAME`, `ENQUOTE_LITERAL` — правильно взять в кавычки;
   - или сверять со **списком разрешённых** значений (`CASE p_sort WHEN 'NAME' THEN 'last_name' WHEN 'SAL' THEN 'salary' END`).
3. Минимум прав у владельца кода, `AUTHID CURRENT_USER` для утилит.
4. Не использовать динамический SQL там, где можно статический.

## Bind-переменные и производительность

Кроме безопасности, bind-переменные дают **переиспользование плана**. `WHERE id = 101`, `WHERE id = 102` — разные тексты, каждый — hard parse и отдельная запись в shared pool. `WHERE id = :id` — один текст для всех значений, один разбор. В статическом PL/SQL переменные и так становятся bind-переменными автоматически; в динамическом — это твоя ответственность.

Обратная сторона — **bind peeking**: план строится по первому подставленному значению и может не подходить для других (одно значение — 1 строка, другое — полтаблицы). Oracle смягчает это механизмом Adaptive Cursor Sharing.

## ? Когда нужен динамический SQL?

Для DDL и других команд, которые нельзя писать в PL/SQL статически (CREATE, ALTER, TRUNCATE, GRANT); когда имя таблицы или столбца известно только при выполнении; когда текст запроса собирается из меняющегося набора условий. В остальных случаях лучше статический SQL: он проверяется при компиляции и отслеживает зависимости.

## ? Чем EXECUTE IMMEDIATE отличается от DBMS_SQL?

EXECUTE IMMEDIATE — встроенный в язык, простой и быстрый, подходит, когда при написании кода известно количество bind-переменных и столбцов результата. DBMS_SQL — пакет с пошаговым API (parse, bind, define, execute, fetch), нужен, когда количество и типы параметров или столбцов становятся известны только при выполнении, а также для описания столбцов результата (DESCRIBE_COLUMNS).

## ? Что такое SQL-инъекция и как от неё защититься в PL/SQL?

Подмена смысла команды через данные, которые вклеиваются в текст динамического SQL: `' OR '1'='1` превращает условие в всегда истинное. Защита: передавать все значения только через bind-переменные (USING); имена объектов, которые нельзя передать через bind, проверять DBMS_ASSERT или белым списком; давать коду минимальные права; не использовать динамический SQL без необходимости.

## ? Можно ли передать имя таблицы через bind-переменную?

Нет. Bind-переменные подставляют только значения, а имена объектов, столбцов и ключевые слова должны быть в тексте команды на момент разбора. Имя приходится вклеивать, поэтому его нужно проверять: DBMS_ASSERT.SQL_OBJECT_NAME, SIMPLE_SQL_NAME или сравнение со списком допустимых.

## ? Зачем bind-переменные, кроме защиты от инъекций?

Переиспользование разобранного запроса: один текст с :id для всех значений — один hard parse и одна запись в shared pool. Литералы делают каждый запрос новым текстом — растёт нагрузка на CPU и конкуренция за shared pool. В статическом PL/SQL переменные становятся bind автоматически.

## ? Как выполнить DDL из PL/SQL?

Только через динамический SQL: `EXECUTE IMMEDIATE 'CREATE TABLE …'`. Статически DDL в PL/SQL не компилируется. Помнить, что DDL делает неявный COMMIT — зафиксирует всё, что было в транзакции до него.

## Тест: Как правильно выполнить TRUNCATE из процедуры?
- TRUNCATE TABLE t; прямо в теле
- DBMS_OUTPUT.PUT_LINE('TRUNCATE TABLE t')
- [x] EXECUTE IMMEDIATE 'TRUNCATE TABLE t'
- OPEN rc FOR 'TRUNCATE TABLE t'
> DDL в PL/SQL — только динамически. Прямая запись не скомпилируется.

## Тест: Можно ли передать имя столбца для ORDER BY через USING?
- Да, как обычный параметр
- [x] Нет, bind-переменные подставляют только значения
- Да, если обернуть в кавычки
- Только в DBMS_SQL
> С bind-переменной `ORDER BY :col` Oracle будет сортировать по константе-строке, а не по столбцу. Имя вклеивают в текст и проверяют белым списком или DBMS_ASSERT.

## Тест: Что не так с EXECUTE IMMEDIATE 'DELETE FROM t WHERE id = 1;'?
- Нужен COMMIT в тексте
- [x] Лишняя точка с запятой в конце SQL-команды
- DELETE нельзя динамически
- Нужно USING
> Для SQL-команды `;` в строке не нужна — будет ORA-00933/ORA-00911. Точка с запятой нужна только в тексте PL/SQL-блока.

## Тест: Какой код защищён от SQL-инъекции?
- 'SELECT * FROM users WHERE login = ''' || p_login || ''''
- 'SELECT * FROM users WHERE login = ' || UPPER(p_login)
- [x] 'SELECT * FROM users WHERE login = :l' с USING p_login
- 'SELECT * FROM users WHERE login = "' || p_login || '"'
> Значение через bind никогда не становится частью текста команды и не может изменить её смысл.

## Тест: Какой инструмент нужен для выгрузки произвольной таблицы, если число и типы столбцов неизвестны заранее?
- EXECUTE IMMEDIATE … INTO
- OPEN FOR с сильным REF CURSOR
- [x] DBMS_SQL с DESCRIBE_COLUMNS
- FORALL
> Только DBMS_SQL позволяет узнать описание столбцов результата и выбирать их значения по номеру во время выполнения.

## Тест: Какая функция проверяет, что строка — допустимое простое имя SQL?
- DBMS_ASSERT.NOOP
- [x] DBMS_ASSERT.SIMPLE_SQL_NAME
- DBMS_SQL.PARSE
- DBMS_UTILITY.NAME_RESOLVE
> SIMPLE_SQL_NAME выбросит ошибку, если в строке есть что-то кроме допустимого идентификатора. NOOP ничего не проверяет.

## Тест: В динамическом SQL 'UPDATE t SET a = :x WHERE b = :x' сколько значений нужно передать в USING?
- Одно, имена совпадают
- [x] Два — связывание по позиции
- Ноль
- Зависит от версии
> В динамическом SQL bind-переменные связываются по позиции, а не по имени: два вхождения — два значения.
