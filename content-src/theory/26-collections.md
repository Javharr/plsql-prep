## Записи (RECORD)

**Запись** — набор полей разных типов под одним именем, как строка таблицы.

```sql
DECLARE
  TYPE t_emp IS RECORD (
    id     employees.employee_id%TYPE,
    name   VARCHAR2(100),
    salary NUMBER := 0
  );
  r t_emp;
  r2 employees%ROWTYPE;             -- запись со структурой таблицы
BEGIN
  r.id := 100;
  r.name := 'King';
  r2 := NULL;                        -- можно присвоить NULL всем полям сразу
END;
```

Записи одного типа можно присваивать целиком (`r_a := r_b`), передавать в процедуры, вставлять строкой: `INSERT INTO employees VALUES r2;`, `UPDATE employees SET ROW = r2 WHERE …`. Сравнивать записи целиком (`r_a = r_b`) нельзя — только по полям.

## Три вида коллекций

| | Ассоциативный массив | Вложенная таблица | VARRAY |
|---|---|---|---|
| Объявление | `TABLE OF … INDEX BY PLS_INTEGER` (или `VARCHAR2(n)`) | `TABLE OF …` | `VARRAY(n) OF …` |
| Индекс | любые целые (в т.ч. отрицательные) или **строки** | 1, 2, 3… | 1..n |
| Размер | неограничен, разреженный | неограничен, может стать разреженным после DELETE | **максимум задан**, всегда плотный |
| Инициализация | не нужна | нужен конструктор или EXTEND | нужен конструктор или EXTEND |
| Хранится в столбце таблицы | нет | да (отдельный сегмент) | да (в строке) |
| Можно в SQL (`TABLE()`) | с 12c, если тип в пакете | да (тип схемы) | да (тип схемы) |
| Порядок | по ключу | сохраняется не гарантированно при хранении | сохраняется |

## Ассоциативный массив (index-by table)

Самый частый в PL/SQL-коде. Не требует инициализации, растёт сам при присваивании.

```sql
DECLARE
  TYPE t_by_name IS TABLE OF NUMBER INDEX BY VARCHAR2(50);
  sal t_by_name;
  k VARCHAR2(50);
BEGIN
  sal('King') := 24000;
  sal('Kochhar') := 17000;
  k := sal.FIRST;                   -- обход по ключам в отсортированном порядке
  WHILE k IS NOT NULL LOOP
    DBMS_OUTPUT.PUT_LINE(k || ': ' || sal(k));
    k := sal.NEXT(k);
  END LOOP;
END;
```

Применение — словарь в памяти: кэш справочника «код → название», чтобы не делать запрос на каждую строку. Обращение к несуществующему ключу — **NO_DATA_FOUND** (проверяй `EXISTS`).

## Вложенная таблица и VARRAY

```sql
DECLARE
  TYPE t_names IS TABLE OF VARCHAR2(50);
  TYPE t_top3  IS VARRAY(3) OF NUMBER;
  names t_names := t_names('A', 'B');    -- конструктор
  top   t_top3  := t_top3();             -- пустая, но инициализированная
  empty t_names;                         -- не инициализирована: NULL
BEGIN
  names.EXTEND;                          -- добавить место
  names(names.LAST) := 'C';
  top.EXTEND(3);
  top(1) := 100;
  -- empty.EXTEND;                       -- ORA-06531: Reference to uninitialized collection
END;
```

- Неинициализированная (атомарно NULL) коллекция → `COLLECTION_IS_NULL` при обращении. Ассоциативного массива это не касается.
- Присваивание элементу за пределами размера → `SUBSCRIPT_BEYOND_COUNT`; за пределами максимума VARRAY → `SUBSCRIPT_OUTSIDE_LIMIT`.
- VARRAY нельзя «продырявить»: удалять элементы можно только с конца (`TRIM`) или все (`DELETE` без параметров).

Типы, объявленные на уровне схемы (`CREATE TYPE t_num_list AS TABLE OF NUMBER;`), можно использовать в столбцах таблиц и в SQL.

## Методы коллекций

| Метод | Что делает |
|---|---|
| `COUNT` | количество элементов (существующих) |
| `FIRST`, `LAST` | наименьший и наибольший индекс (NULL, если пусто) |
| `NEXT(i)`, `PRIOR(i)` | следующий / предыдущий существующий индекс |
| `EXISTS(i)` | есть ли элемент с индексом i (не бросает исключений) |
| `EXTEND`, `EXTEND(n)` | добавить пустые элементы (не для ассоциативных массивов) |
| `TRIM`, `TRIM(n)` | удалить с конца (не для ассоциативных) |
| `DELETE`, `DELETE(i)`, `DELETE(i, j)` | удалить все / один / диапазон (для VARRAY — только все) |
| `LIMIT` | максимум для VARRAY (NULL для остальных) |

**Ловушка разреженности:** после `DELETE(i)` цикл `FOR i IN 1..c.COUNT` упадёт на «дырке» с NO_DATA_FOUND, а `FOR i IN c.FIRST..c.LAST` — тоже. Для разреженных коллекций обходи через `FIRST`/`NEXT`. Для пустой коллекции `FOR i IN c.FIRST..c.LAST` падает с VALUE_ERROR (границы NULL), а `1..c.COUNT` — безопасен.

## Коллекции в SQL

Вложенную таблицу или VARRAY типа схемы можно использовать как таблицу:

```sql
CREATE TYPE t_num_list AS TABLE OF NUMBER;
/
SELECT * FROM employees
 WHERE employee_id IN (SELECT column_value FROM TABLE(t_num_list(100, 101, 102)));
```

Полезно, чтобы передать список значений в запрос одним параметром вместо динамического `IN (…)`. Обратное — собрать результат запроса в коллекцию: `BULK COLLECT INTO` или `CAST(MULTISET(SELECT …) AS t_num_list)`.

**Конвейерные функции** (`PIPELINED`) возвращают коллекцию построчно через `PIPE ROW` и используются в `FROM TABLE(f(…))` — можно стримить результат сложной PL/SQL-обработки в SQL без хранения всего набора в памяти.

## ? Какие виды коллекций есть в PL/SQL и чем они отличаются?

Ассоциативный массив (INDEX BY) — индекс по числам или строкам, разреженный, без инициализации, только в PL/SQL. Вложенная таблица — индекс с 1, без верхней границы, нужна инициализация конструктором, может храниться в столбце и использоваться в SQL. VARRAY — с фиксированным максимумом, всегда плотный, хранится в строке таблицы, сохраняет порядок.

## ? Когда использовать ассоциативный массив?

Как словарь или кэш в памяти: «код → значение», чтобы не обращаться к таблице на каждой строке; для временных наборов с произвольными или строковыми ключами; для BULK COLLECT. Не нужна инициализация, элемент появляется при присваивании. Ограничение — живёт только в PL/SQL и не хранится в таблицах.

## ? Что будет при обращении к элементу, которого нет?

Для ассоциативного массива и вложенной таблицы с удалённым элементом — NO_DATA_FOUND. Для индекса за пределами текущего размера вложенной таблицы или VARRAY — SUBSCRIPT_BEYOND_COUNT; за пределами максимума VARRAY — SUBSCRIPT_OUTSIDE_LIMIT. Для неинициализированной коллекции — COLLECTION_IS_NULL. Проверять безопасно через EXISTS.

## ? Какие методы коллекций ты знаешь?

COUNT, FIRST, LAST, NEXT, PRIOR, EXISTS, EXTEND, TRIM, DELETE, LIMIT. Для обхода разреженной коллекции — FIRST и NEXT в цикле WHILE, а не FOR 1..COUNT.

## ? Как передать список id в SQL-запрос из PL/SQL?

Объявить тип коллекции на уровне схемы (CREATE TYPE … AS TABLE OF NUMBER), заполнить переменную и использовать `WHERE id IN (SELECT column_value FROM TABLE(:list))` или соединение с TABLE(). Это лучше, чем склеивать строку для динамического IN: нет SQL-инъекций и одного разбора на каждый набор значений.

## ? Что такое конвейерная (PIPELINED) функция?

Функция, возвращающая коллекцию, которая отдаёт строки по одной через PIPE ROW, пока ещё работает. Вызывается в FROM TABLE(f(…)) как обычная таблица. Позволяет встроить сложную PL/SQL-обработку в SQL (ETL-трансформации), не собирая весь результат в памяти.

## Тест: Какой тип коллекции не требует инициализации конструктором?
- Вложенная таблица
- VARRAY
- [x] Ассоциативный массив
- Все требуют
> Ассоциативный массив готов к использованию сразу: элемент создаётся при присваивании. Вложенной таблице и VARRAY нужен конструктор или они будут NULL.

## Тест: Какая коллекция поддерживает строковые ключи, например sal('King')?
- VARRAY
- Вложенная таблица
- [x] Ассоциативный массив INDEX BY VARCHAR2
- Никакая
> Только ассоциативный массив может индексироваться строками.

## Тест: Объявили names t_names; (вложенная таблица без конструктора) и вызвали names.EXTEND. Что будет?
- Добавится один элемент
- [x] Ошибка COLLECTION_IS_NULL (ORA-06531)
- Ничего не произойдёт
- Ошибка компиляции
> Неинициализированная вложенная таблица — атомарный NULL. Нужно `names := t_names();` или конструктор при объявлении.

## Тест: Коллекция с индексами 1, 2, 3, 4, сделали DELETE(2). Что вернёт COUNT?
- 4
- [x] 3
- 2
- NULL
> COUNT считает только существующие элементы. LAST при этом останется 4 — коллекция стала разреженной.

## Тест: Как безопасно обойти разреженную коллекцию?
- FOR i IN 1..c.COUNT LOOP
- FOR i IN c.FIRST..c.LAST LOOP без проверок
- [x] i := c.FIRST; WHILE i IS NOT NULL LOOP … i := c.NEXT(i); END LOOP;
- FOR i IN REVERSE 1..c.COUNT LOOP
> FIRST/NEXT перескакивают через удалённые элементы. Циклы по диапазону упадут с NO_DATA_FOUND на «дырке».

## Тест: Какая коллекция имеет фиксированный максимальный размер?
- Ассоциативный массив
- Вложенная таблица
- [x] VARRAY
- Ни одна
> VARRAY(n) не может содержать больше n элементов — иначе SUBSCRIPT_OUTSIDE_LIMIT.

## Тест: Что нужно, чтобы использовать коллекцию в SELECT … FROM TABLE(коллекция)?
- Объявить тип в анонимном блоке
- [x] Объявить тип на уровне схемы (CREATE TYPE) или в спецификации пакета (12c+)
- Использовать только VARRAY
- Ничего, работает с любой коллекцией
> SQL-движок должен знать тип. Локальные типы PL/SQL-блока ему не видны.

## Тест: Что вернёт EXISTS(10) для коллекции из 3 элементов?
- Исключение SUBSCRIPT_BEYOND_COUNT
- NULL
- [x] FALSE
- TRUE
> EXISTS никогда не бросает исключений (кроме случая с неинициализированной коллекцией — там тоже FALSE). Им и проверяют наличие перед чтением.
