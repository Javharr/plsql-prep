## Виды подзапросов

Подзапрос — `SELECT` внутри другого запроса. Различают по тому, **что** он возвращает и **где** стоит:

| Вид | Возвращает | Пример использования |
|---|---|---|
| Скалярный | одно значение (1 строка × 1 столбец) | `WHERE salary > (SELECT AVG(salary) FROM employees)` |
| Многострочный | столбец значений | `WHERE department_id IN (SELECT …)` |
| Inline view | таблицу | `FROM (SELECT …) t` |
| Коррелированный | зависит от строки внешнего запроса | `WHERE salary > (SELECT AVG(salary) … WHERE department_id = e.department_id)` |

Если скалярный подзапрос вернул **больше одной строки** — ошибка `ORA-01427: single-row subquery returns more than one row`. Если **ни одной** — результат NULL (а не ошибка).

## Коррелированный подзапрос

Ссылается на столбцы внешнего запроса, поэтому логически выполняется **для каждой строки** внешнего запроса:

```sql
-- сотрудники, получающие больше среднего по своему отделу
SELECT e.last_name, e.salary, e.department_id
  FROM employees e
 WHERE e.salary > (SELECT AVG(i.salary)
                     FROM employees i
                    WHERE i.department_id = e.department_id);
```

Оптимизатор часто переписывает такие подзапросы в соединение (unnesting), так что «выполняется для каждой строки» — логическая модель, а не обязательно реальный план. Ту же задачу решает аналитика: `AVG(salary) OVER (PARTITION BY department_id)` — за один проход таблицы.

## IN против EXISTS

```sql
SELECT d.* FROM departments d
 WHERE EXISTS (SELECT 1 FROM employees e WHERE e.department_id = d.department_id);

SELECT d.* FROM departments d
 WHERE d.department_id IN (SELECT e.department_id FROM employees e);
```

- `EXISTS` проверяет только **факт наличия** хотя бы одной строки и останавливается на первой найденной. Что написано в SELECT подзапроса — неважно (`SELECT 1`, `SELECT *`, `SELECT NULL` — одно и то же).
- `IN` сравнивает значение со списком значений.
- По результату `IN` и `EXISTS` эквивалентны. По скорости в современных версиях Oracle обычно тоже: оптимизатор превращает оба в semi-join.
- **Разница в отрицании:** `NOT IN` ломается, если в подзапросе есть NULL (вернёт 0 строк), а `NOT EXISTS` — нет. Поэтому для «чего нет» выбирают `NOT EXISTS`.

## Inline view и WITH (CTE)

Подзапрос во `FROM` — **inline view**, временная таблица на время запроса. Через неё обходят ограничения порядка выполнения: отфильтровать по алиасу, по результату аналитической функции, взять топ-N после сортировки.

`WITH` (Common Table Expression) — то же самое, но с именем и в начале запроса. Читается лучше и позволяет сослаться на один и тот же подзапрос несколько раз:

```sql
WITH dept_avg AS (
  SELECT department_id, AVG(salary) AS avg_sal FROM employees GROUP BY department_id
)
SELECT e.last_name, e.salary, a.avg_sal
  FROM employees e
  JOIN dept_avg a ON a.department_id = e.department_id
 WHERE e.salary > a.avg_sal;
```

`WITH` бывает и рекурсивным — для иерархий (см. тему «Иерархические запросы»).

## Операции над множествами

Объединяют результаты двух запросов «по вертикали»:

| Оператор | Результат | Дубли |
|---|---|---|
| `UNION ALL` | все строки обоих запросов | оставляет |
| `UNION` | все строки обоих запросов | **убирает** (сортировка/хеширование) |
| `INTERSECT` | строки, которые есть в обоих | убирает |
| `MINUS` (`EXCEPT` в стандарте, в Oracle 21c+ тоже) | строки первого, которых нет во втором | убирает |

Правила:

- число столбцов и их типы должны совпадать по позициям;
- имена столбцов результата берутся из **первого** запроса;
- `ORDER BY` — один, в самом конце, и он сортирует весь результат;
- NULL в этих операциях считаются равными друг другу.

> **На собеседовании:** `UNION ALL` быстрее `UNION`, потому что не ищет дубли. Если дублей быть не может (например, объединяешь разные периоды) или они нужны — всегда `UNION ALL`.

## ? Чем IN отличается от EXISTS?

IN сравнивает значение со списком, который вернул подзапрос; EXISTS проверяет, есть ли хотя бы одна строка, и останавливается на первой. По результату для положительной проверки они эквивалентны, и в современных версиях Oracle оптимизатор строит для них одинаковый план (semi-join). Главная разница — в отрицании: NOT IN возвращает пустой результат, если подзапрос вернул NULL, а NOT EXISTS работает корректно.

## ? Что такое коррелированный подзапрос?

Подзапрос, который ссылается на столбцы внешнего запроса и поэтому логически вычисляется для каждой его строки. Пример — «зарплата больше средней по своему отделу». Часто его можно заменить соединением с агрегатом или аналитической функцией `AVG() OVER (PARTITION BY …)`, что обычно эффективнее.

## ? Чем UNION отличается от UNION ALL?

UNION ALL просто склеивает результаты двух запросов. UNION дополнительно убирает дубли, для этого ему нужна сортировка или хеширование всего результата — это дороже. Если дубли невозможны или нужны, используют UNION ALL.

## ? Что будет, если скалярный подзапрос вернёт несколько строк? А ни одной?

Несколько строк — ошибка ORA-01427 single-row subquery returns more than one row. Ни одной — подзапрос даёт NULL, ошибки нет. В PL/SQL с `SELECT INTO` наоборот: ни одной строки — NO_DATA_FOUND, больше одной — TOO_MANY_ROWS.

## ? Зачем нужен WITH (CTE)?

Даёт подзапросу имя: запрос читается сверху вниз, один и тот же подзапрос можно использовать несколько раз, Oracle может материализовать его один раз. Ещё рекурсивный WITH строит иерархии. Логически это то же, что inline view.

## ? Какие правила у UNION, INTERSECT, MINUS?

Одинаковое число столбцов и совместимые типы по позициям; имена столбцов берутся из первого запроса; ORDER BY один и только в конце; дубли убираются (кроме UNION ALL); NULL считаются равными.

> `=` ожидает одно значение. Для списка нужно `IN`, `= ANY` или агрегат в подзапросе.

## Тест: Что написать в SELECT подзапроса EXISTS, чтобы работало быстрее?
- SELECT *
- SELECT 1
- SELECT NULL
- [x] Неважно — EXISTS проверяет только наличие строк
> EXISTS не использует значения столбцов, только факт наличия строки. `SELECT 1` — просто соглашение для читаемости.

## Тест: Какой вариант надёжно найдёт клиентов без заказов, даже если в orders.cust_id бывают NULL?
- cust_id NOT IN (SELECT cust_id FROM orders)
- [x] NOT EXISTS (SELECT 1 FROM orders o WHERE o.cust_id = c.cust_id)
- cust_id <> ALL (SELECT cust_id FROM orders)
- cust_id NOT IN (SELECT DISTINCT cust_id FROM orders)
> NOT IN и `<> ALL` дают UNKNOWN при NULL в подзапросе и возвращают 0 строк. NOT EXISTS от NULL не зависит.

## Тест: В запросе A 10 строк, в B 8 строк, 3 строки совпадают. Сколько вернёт A UNION ALL B?
- 15
- [x] 18
- 13
- 3
> UNION ALL дубли не убирает: 10 + 8 = 18. UNION вернул бы 15 (если внутри A и B дублей нет).

## Тест: Те же A (10 строк) и B (8 строк), 3 общих. Сколько вернёт A MINUS B?
- 3
- 5
- [x] 7
- 2
> MINUS — строки A, которых нет в B: 10 − 3 = 7 (если внутри A нет дублей).
